## ②「読む」は見開きで開き、「書く」で戻れる

実機の状態:

- 「読む」は**右ペイン**（幅が狭い）で電子書籍を開いていた。見開きの判定は紙面幅×2
  （当時 420×2＋ガター = 846px）を要求するため、ペイン幅では常に単ページだった。
- 読書面を開いている間は `canNavigate` を丸ごと落としていたため、上部ナビの
  **「書く」も「読む」も「確認」も押せなかった**（＝読みから出る導線が面の中だけ）。

対応:

1. **「読む」＝本文を全幅の読書面で開く**。既存の Reading Focus
   （`.ebook-reading-focus-surface`）へ入る。導線は上部ナビ → `readingFocusIntent`
   （`{open, token}`）→ `AppWorkspace` の effect 1本で、状態の持ち主は変えない。
   同じ要求の再描画で開き直さないよう token で1回だけ適用する。
2. **「書く」は読書面を開いていても押せる**。`WorkspaceModeNavigation` に `readingOpen` を
   渡し、「書く」は常に有効、「読む」「確認」だけを止める（モックC03の
   「『書く』は現在文書の編集へ戻る」）。押すと読書面を閉じて編集へ戻る
   （読書位置の保存と本文への復帰は既存の退出処理をそのまま通す）。
   本全体の読書面（Book Scope Reader）も同じ導線で閉じる。
3. 読書面は**プレビュー列の設定に依存させない**。以前は `previewVisible` を要求していたため、
   プレビューを閉じている利用者には「読む」が無反応になった（依存を外した理由を
   ソースにコメントで残した）。

## ②の実体 — 見開きは紙の内側の余白に負けていた

紙面の幅は `--ebook-spread-width = 紙面×2＋ガター` で、**紙の内側の余白を数えていなかった**。
そのため見開きモードでも紙の内側に2列目が入らず、DOM実測では

- 修正前: 紙 916px・本文域 836px・**段落は1本の矩形（幅 836）＝1列**
- 修正後: 紙 996px・本文域 916px・**段落は列ごとの矩形（幅 455）＝2列**

つまり「見開きにならない」は、閾値ではなく**紙幅の計算漏れ**だった。紙幅に
`--ebook-sheet-pad-x` を両側ぶん足し、本文域を `紙幅 − 余白×2 − 罫線2px` にした。
容器の閾値は `920px → 1090px`（紙455×2＋ガター6＋紙の余白＋章の余白が実際に並ぶ幅。
CSS の `@container` と JS の `EBOOK_SPREAD_CONTAINER_MIN_WIDTH` を同じ値にした）。

## ④ 紙面の余白

モック04の基準（一枚455px・左右内側39px）へ寄せた。

| | 修正前 | 修正後 |
| --- | ---: | ---: |
| 紙面の幅 | `min(420px, 100vw−56px)` | `min(455px, 100vw−56px)` |
| 紙の内側の余白 | `clamp(14px, 2vw, 22px)` | `clamp(22px, 3vw, 39px)` |
| 紙の左端〜本文（1440実測） | 23px | **40px** |
| 本文域（1440実測） | 846px（420×2＋6） | **916px（455×2＋6）** |
| 紙の外枠（1440実測） | 892px | 996px |

## 画像との差・未決

- 見開きは**1枚の紙に2列**（中央ガター6px）で表現している（画面04の第二調整で決めた形）。
  モック04の画像は `.book-page` が2枚の独立した紙。**2枚の紙に分けるかどうかは未決**
  （分けると罫線と影が2つになり、静けさが増すかわるくなるかは実機で見るしかない）。
- 右列は先頭から本文が始まる（走りヘッダは左列のみ）。モック04は両ページに running header を持つ。
