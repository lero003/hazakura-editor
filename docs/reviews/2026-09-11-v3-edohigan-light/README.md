## 何をしたか

**江戸彼岸の紙がモックと真逆だった。** モック `reference/mock-styles.css` が定義するテーマは
`:root`（ライト）・`.dark`・`.edohigan` の**3つだけ**で、`.edohigan` は
`--bg:#fbf4f2 / --paper:#fffcf8 / --ink:#453735 / --accent:#975b68` の**明るい桜色**。
実アプリは `--bg:#2a2030` の暗色「薄暮」で、画面20（江戸彼岸・えるモード）は成立していなかった。

モックPNGの実画素でも確認（支配色ヒストグラム）:

| 画像 | 支配色 | 意味 |
| --- | --- | --- |
| `20-edohigan.png` | `#fffcf8` 47.9% / `#fbf4f2` 3.2% | **明色**（モック `.edohigan` と一致） |
| `19-dark.png` | `#1d2a23` 28.4% / `#18241e` 4.5% | モック `.dark` と一致 |

オーナー判断（「振り切る」＝段階2と同じ方針）で、**モックの明色へ作り替えた**。

1. **テーマ色**: 紙 `#fffcf8` / 地・chrome `#fbf4f2` / ナビ `#f4e9e6`（不透明化）/ インク `#453735` /
   補助 `#79655e` / アクセント `#975b68` / accent面のインク `#ffffff`。追加・削除行の背景は
   モックの `#e7efdf` / `#f7e2e1`。文字のグロー（暗色前提）は撤去。
2. **罫線はモック値から意図的に離す**: モックの `#e6d8d0` / `#c9b6ae` は紙面比 1.36 / 1.90 で、
   確立済みの階層契約（`--border` 1.45〜1.7、`--border-strong` ≥2.1・差 ≥0.4）を満たさない。
   同じ色相のまま紙面からの距離を伸ばし `#dccac0`（1.55）/ `#bfa8a0`（2.20）とした（B案の前例）。
3. **ナビ面を不透明に**: 明色では半透明の自動検査ができず、実描画経路へ逃げる理由もない。
   `--nav-surface: #f4e9e6`（モックの `--side`）にして、本文・補助文字の 4.5:1 を自動検査へ戻した。
4. **えるモード**: 暗色系グループ（dark/yakou/crt/shinkai）から edohigan を外し、専用の明色
   ブロックを追加。**机 `#fbf4f2` の上に紙 `#fffcf8`**（`.cm-content` の本文カラムへ紙を敷く）。
   モックの03（えるモード）も紙 `#fffefb` を支配色としており、「テーマの紙をえるモードでも使う」
   という構造に合わせた。
5. **装飾**: シェーダーの空を「薄暮の彼岸空」から「明るい桜空」へ。明色では**加算をやめ、
   桜色へ寄せる**方式に変更（加算は白飛びして紙面が濁る）。花びらはモックの色
   （`#ebc6cd` / `#e3b5bf`）にし、**左右の余白だけ**へ（`sideMask`。狭い窓では本文が幅を取るため
   自然に消える）。ビネットは暗くせず端をわずかに桜色へ寄せる。前景オーバーレイの z は
   `--z-crt-top`(1200) → `--z-base`(1) へ下げ、**モーダル(100)・パレット(1100)より手前へ出ない**
   ようにした（`pages/20-edohigan.md:28` の要求）。

### ついでに見つけて直した不具合 — えるモードの分割バー

えるモードでは `.editor-preview-grid` が1カラムになるが、`.pane-resizer` が残るため
**2行目へ落ちて行いっぱいに伸び、`--border` の帯**になっていた。

| ウィンドウ | 分割バーの高さ | 格子 |
| --- | --- | --- |
| 1440×850 | **323px**（窓の約38%） | `526.625px 323.375px` |
| 1280×633 | 221px | `411.875px 221.125px` |
| 960×640 | 225px | `415.375px 224.625px` |
| 1600×1000 | 393px | `607.375px 392.625px` |

**ライトテーマ（`#e0d5bd`）でも同じ**だったため、江戸彼岸の色替えで生じたものではなく
テーマ非依存の既存不具合。L モードに分割する相手はいないので `.pane-resizer` を落とした
（修正後: `display: none` / 高さ0 / 格子 `850px` の1行）。

## 画像との差・未決

- **えるモードの本文幅**: 実装 720px、モック 724px（差4px）。L モード共通の値なのでこのスライスでは動かしていない。
- **紙の占有率**: モックは紙が 47.9% を占めるのに対し、1440px 幅では机が 49.1%。本文カラムが 720px 固定のためで、
  「机の上の紙」という構造自体は一致している。
- **L モードの全テーマ方針（新規の要判断）**: モックの03（えるモード）の紙は `#fffefb` ＝**ライトテーマの紙**だが、
  実アプリのえるモードはセピアの閉じたパレット（`#faf6ee`）を使う。今回は edohigan だけモック準拠にした。
  「えるモードはテーマの紙を使う」へ全テーマを寄せるか、セピアを維持するかは**未決**。
- **花びらの枚数・密度**: モック自身が「静止画です」と明記しており、枚数・FPS の指定ではない。左右の余白のみ・
  狭幅で消える、という構造だけを合わせた。実機での負荷は未測定。

## 残リスク・未受入

- **WebGL キャンバスはヘッドレス撮影で写らない**ため、装飾（桜空・花びら）の見た目そのものは**実機確認が必要**。
  上の証跡は面の色（紙・机・ナビ・chrome）と DOM の配置についての証拠である。
- native での VoiceOver、200% 文字、再起動後のテーマ保持、別窓との同期、実 IME は**未実施**。
- 起動スプラッシュ（`.edohigan-boot`）は撮影時に外している（ヘッドレスでは起動アニメーションが完了しない）。
  実機でスプラッシュから紙面へ自然に移ることを確認する必要がある。
