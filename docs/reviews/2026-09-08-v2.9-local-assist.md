## 実装と判断

- 完成案はsanitize後4,000 Unicodeコードポイント以内。超過時は切り捨てず拒否し、有効な前案を保持する。
- 案に実応答のmodelId/latencyを保持し、Diffに生成元を表示。旧応答は不明。設定値から補完しない。
- Systemのstream/非stream事前検査を共通化。既存string wireを維持し、復旧可能な理由を分類する。
- 自作日本語12原稿の評価CLIと、明示要求時だけのtoken観測を追加。通常Rust要求は計測しない。
- 評価でhelperが先頭のコードフェンスを削る問題を確認し修正。対になったMarkdownラッパーだけを限定的に除去し、コードや曖昧な囲みは残す。
- native追加指示で裸の `HAZAKURA_TEXT_END` が完成案に残る問題を再現。sanitize後も予約区切り文字が残る案は生成完了・レビュー・反映の各段で拒否し、有効な前案へ戻す。
- nativeの完了ステータスの英語漏れと、非同期失敗イベントが分類を経由しない経路を修正。形式不明の案は本文を変更せず再依頼を案内する。

## 再レビュー対応（745399a1へのR1 / R2 / R3）

- **R1:** 別窓の実listenerが同じ会話のApply失敗を受け、分類済みalert・status・feedbackを更新する。
  失敗では会話と前案を残し、成功/破棄だけリセットする。render testで日本語alert、
  前案を使う追加指示、他会話/会話IDなしのイベント無視を検証した。
- **R2:** 別窓はrequestId付き取消を専用Tauri commandでmainへ送る。Rustで窓・配布レーン・

  対象取得中の取消、依頼IPCより先に取消が届かないこと、helper起動前/起動後、遅延応答、
  完了後の取消、再生成中の古い取消を検証。生成とnative停止の両方が終わるまでロックを維持する。
  native確認でmainの「生成中」が取消後も残ることを見つけ、status更新とja/kana表示も修正した。
- **R3:** アプリの周辺文書8,000文字超過と、モデルのcontext容量不足を分離する。
  後者には対象短縮/新しい会話を案内し、8,000文字超過や前案保持を推測して断定しない。
  ja/kana/enで検証。string wireは維持し、token強制上限や新しい生成方式は導入しない。

## 取消の再追補（6a5c15b5へのR2-a / R2-b）

R1/R3は維持。R2は前回の論理取消だけではnative開始待ちと別窓の操作再開が揃っていなかった。
今回の変更は次の2点に限定する。

- **R2-a:** mainはnative生成前にrequestIdを予約し、予約完了を待ってworkerへ投入する。
  取消は同じ予約を待ってID付きで送る。Rustはhelper未起動/ハンドル未登録でも取消フラグを保持し、
  ハンドル登録時に引き継ぐ。終了時は該当IDだけを解放し、古い取消/解放を次の要求へ適用しない。
  予約は同時に1件、main窓からのみ。任意イベント権限・helper wire・モデル方式は増やさない。
  アプリ終了の既存stop-allも予約中の要求を止める。
- **R2-b:** 前案復帰と採用権限の失効は即時。`cancelling`で別窓を「取り消し中」に保ち、
  生成Promise・停止Promise・native予約解放の完了後、mainのロック解除に続いて`cancelled`を通知する。
  停止待ちのstarted/partialは無視し、入力・依頼ボタンを無効にする。
  完成/失敗の終端通知も予約解放後に送る。既存sidebarも中間通知で会話を終了しない。

ローカル検証: 全Vitest **230ファイル/2,010件**、Rust **372件（2 ignored）**、
App Store surface **111件**、型検査・Vite・App Store preview native build・Rust fmtが成功。
Rustの新試験は`spawn_blocking`でworkerを投入し、helper起動後・ハンドル登録前を同期点で止めて
取消を入れ、取消エラー/子プロセス回収/失敗回数不変を確認する。worker投入前の取消も別試験で固定。
フロントの統合試験はmainの実cancelJobが送る通知を別窓の実listenerへ届け、停止Promiseを保留したまま
入力不可・依頼不可・古いpartial非表示を確認し、停止後の操作再開まで検証する。

今回のnative実操作は未実施（利用中のアプリの再起動を避けた）。前節のnative記録は6a5c15b5時点の
通常操作であり、今回の開始待ち競合/停止待ちUIのnative保証へ読み替えない。
IME/VoiceOver/旧OS、CIまたは提出用署名済みRCの証跡も未確認。版数更新・freezeは保留を維持する。

## 再実行

```bash
npm run build:apple-assist-helper:live
node --test scripts/local-assist-evaluation-checks.test.mjs
node scripts/evaluate-local-assist.mjs --helper binaries/hazakura-local-assist-helper-aarch64-apple-darwin --output evaluation.local.json --repeats 3
swift test --package-path src-helpers/apple-assist
```

arm64以外では該当architectureのhelperを指定する。評価は自作fixtureのみを読み、一般利用者の
原稿を収集しない。レポートは原稿由来の候補を含むため、追跡外のローカル成果物として扱う。
機械チェックは数値等の部分一致と完成応答の判定であり、意味保持や自然さは人間が確認する。
