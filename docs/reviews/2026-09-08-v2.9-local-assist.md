## 実装と判断

- 完成案はsanitize後4,000 Unicodeコードポイント以内。超過時は切り捨てず拒否し、有効な前案を保持する。
- 案に実応答のmodelId/latencyを保持し、Diffに生成元を表示。旧応答は不明。設定値から補完しない。
- Systemのstream/非stream事前検査を共通化。既存string wireを維持し、復旧可能な理由を分類する。
- 自作日本語12原稿の評価CLIと、明示要求時だけのtoken観測を追加。通常Rust要求は計測しない。
- 評価でhelperが先頭のコードフェンスを削る問題を確認し修正。対になったMarkdownラッパーだけを限定的に除去し、コードや曖昧な囲みは残す。
- native追加指示で裸の `HAZAKURA_TEXT_END` が完成案に残る問題を再現。sanitize後も予約区切り文字が残る案は生成完了・レビュー・反映の各段で拒否し、有効な前案へ戻す。
- nativeの完了ステータスの英語漏れと、非同期失敗イベントが分類を経由しない経路を修正。形式不明の案は本文を変更せず再依頼を案内する。

## 日本語の実モデル評価

macOS 26.6.2 / SDK 26.5、modelId `apple:foundation-models:system-default`。
モデルrevisionはAPIから未取得。基点 `c182c536` に未コミットの評価/修正を加えたローカルビルド。
各レポートにhelper SHA-256、基点commit、dirty有無、原稿条件、応答、所要時間を記録した。

| 評価 | helper SHA-256 | 完成案 | 失敗 | 初回 / 取消後再生成 |
|---|---|---|---|---|
| 初回、12原稿×3＋追加指示3＋取消後1 | `283019067ffab068edcfb347561812cf82d8683bcfa27c26534bd381798dee09` | 35 / 40 | リンク原稿のunsupported_language 3、コード原稿のvalidation 2 | 1,136 / 459 ms |
| フェンス修正後、12原稿×1＋追加指示1＋取消後1 | `f93b49791549f136db5826852f6c4c81048d29fc5c84501f57af29b1c194f919` | 13 / 14 | リンク原稿のunsupported_language 1 | 1,084 / 750 ms |

いずれも全要求成功ではないためCLI exit 1。修正後はコードフェンスとコードを保持したが、
周囲の説明文を落とした。引用の `>` 脱落、表の説明欠落、文体変更への不追従も残る。
初回には表を文章へ変える出力もあった。**完成案応答の成功と文章品質の合格は別**。
raw helperのTEXTラッパー検出は既存アプリsanitize前の観測であり、それだけで製品への混入とは判断しない。
nativeで確認した裸の区切り文字混入は別の再現として上記修正に含めた。

初回はfresh helperという意味で、OSモデルキャッシュの完全coldではない。後続は同じhelperで
モデルを再利用し、sessionは要求ごとに新規。取消試験はpartial受信後のhelper直接停止と
新helperでの完成案成功であり、native取消ボタンやRust supervisorの実機検証の代替ではない。

計測できた完成案ではinstructions 80 tokens、prompt 116–191 tokens、contextSize 4,096。
入力の各要素の観測であり、出力token数・残予算・推論メモリを測れたとは扱わない。
D17の強制予算制限は追加しない。旧OS実行とピークメモリは未確認。

## 再実行

```bash
npm run build:apple-assist-helper:live
node --test scripts/local-assist-evaluation-checks.test.mjs
node scripts/evaluate-local-assist.mjs --helper binaries/hazakura-local-assist-helper-aarch64-apple-darwin --output evaluation.local.json --repeats 3
swift test --package-path src-helpers/apple-assist
```

arm64以外では該当architectureのhelperを指定する。評価は自作fixtureのみを読み、一般利用者の
原稿を収集しない。レポートは原稿由来の候補を含むため、追跡外のローカル成果物として扱う。
機械チェックは数値等の部分一致と完成応答の判定であり、意味保持や自然さは人間が確認する。

## Nativeと自動検証

修正後のローカルApp Store previewアプリを再起動し、自作29文字の原稿で確認した。
初回校正→追加指示→mainの2回目のDiff→明示反映→⌘Zで原文復帰が成功。
元文/案/生成元（Apple Intelligence）/未反映の日本語表示、反映後dirty、Undo後cleanを
macOS accessibility treeで照合。検証原稿は保存せず閉じ、アシスト設定を検証前へ戻した。

同じ追加指示の再実行で区切り文字は再発しなかったが、確率的なモデル出力なので
それだけで修正成功とはしない。混入した応答を固定した失敗テストから、生成時の前案復帰、
レビューの反映不可、UIを経由しない反映の拒否まで確認した。
