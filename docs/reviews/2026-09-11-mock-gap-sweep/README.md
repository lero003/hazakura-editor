## 調べた範囲（正直に）

今回は**スポット**である。突き合わせたのは **01 はじめの画面 / 02 編集（上部バー・タブ行・ペイン見出し・
ステータスバー）/ サイドバー / 11 書き出し** の4面。残り（03・05・06・07・09・10・12・13・14・17・18・21・22・23・24）は
**未突き合わせ**。第1〜3弾の実機フィードバックで既に詰めた面は重複を避けて浅く見ている。

方法は3つ併用:
1. モックの公式スクリーンPNGを読む（`reference/screens/`）
2. モックのDOMをブラウザで描いて寸法を測る（`reference/index.html`）
3. 実アプリfixtureの同じ要素をDOMで確認（文字列は `src/lib/locale/*` の有無でも裏取り）

## 意図的な差として**維持**してよいと判断したもの

| モック | 実アプリ | 理由 |
|---|---|---|
| 起動画面の主ボタンは2つ（フォルダを開く / ＋新しく書く） | 3つ（+ ファイルを開く） | 既存機能の保持（`03-visual-review-checklist` の「機能保全」）。削らない |
| サイドバー下は「フォルダ内を検索 + 使い方」 | 「フォルダ内を検索 + ゴミ箱」 | 第2弾⑩の**オーナー指示**（ゴミ箱を並べたい）。モックより優先 |
| 編集ツールバーに **Markdown / えるモード** の2つ | 6モードの行 | 機能が増えている（プレビュー/電子書籍/アウトライン/参照/差分）。A案で置き場を整理するのが筋 |
| 見出しコピー「ことばに、余白を。」 | 「続きから書く」 | コピーの好み。**オーナー判断**（勝手に変えない） |
| えるモードの背景は黄寄りの紙 | 中立の紙（#fffefb） | 第2弾⑥の**オーナー指示** |

## 推奨

1. **B + C（小物）を1スライス**で寄せる。1行〜1枚の追加で、モックの「静けさ」と「行き先の見える化」に効く。
   B1（ローカル明示）はこの製品の思想にも合う。
2. **A（サイドバーの「この文書」節）はオーナー判断**。見た目の一致は大きいが、タブ行の6モードを移す
   構造変更なので、別スライスとして設計してから着手する。
3. 未突き合わせの15面は、**次のスライスとして1面ずつ**モック起点で潰す（今回の方法をそのまま使う）。
