# UI-G3 — 紙面／ナビ面トークンと7テーマの面の分離

Status: Implemented; native acceptance pending
Scope: モックの「紙面」と「ナビ面」を意味トークンとして新設し、全7テーマへ適用
Authority: Evidence
Date: 2026-09-10

## 何をしたか

モック（`20260909_hazakura-ui-implementation`）は `--paper`（本文の紙面）と `--side`（操作部・ナビ）を
汎用 `--surface` から分けている。現行アプリは両方を持たず、サイドバーも本文も同じ面だった。
これは**全画面に効く差**なので、まずここを揃えた（棚卸しは [v3-mock-gap-inventory.md](../../v3-mock-gap-inventory.md)）。

| Commit | 変更 |
| --- | --- |
| （本スライス） | `--surface-paper` / `--nav-surface` を新設し、7テーマで定義。読む・書く面は紙面、サイドバー・chrome・設定レールはナビ面へ |
| （同上） | エディタ面 `--cm-bg` を全テーマで紙面トークンへ統一。設定ダイアログの半透明ガラスを不透明な紙面へ |
| （同上） | 補助文字のコントラスト調整（ライト / shokou / crt）と、テーマ整合テストの単一ソース化 |

`--surface`（汎用の白）は残し、**全 surface を一括着色しない**（C04の指示）。
色の定義元は各テーマファイル、消費者は `var(--surface-paper)` / `var(--nav-surface)` の参照だけにした。

| edohigan（江戸彼岸） | `#342230` | `rgba(46, 29, 44, 0.78)` | 既存の読む面（不透明）を維持。ナビは透過を残す |

`--workspace-chrome-paper: #fffefb`）は、この2トークンへ一本化した。7テーマすべてが同じ面の構成になる。

## 制約の扱い

- **不透明化**：モックの C08「文字を読む面は不透明に」に従い、edohigan / shinkai のエディタ面を
  半透明から不透明な紙面へ変えた。水流・チリの透過はサイドバーとガターに残す（テーマの性格は維持）。
- **汎用surface**：`--surface` `#ffffff` は変えていない。カード・入力・ダイアログ部品の白はそのまま。
- **L Mode**：`[data-l-mode="on"]` は独自の暖色パレットを持ち、`--cm-bg: var(--bg)` を使う。
  今回は触っていない（えるモードの紙は別判断）。
- **文字の大きさ・行間**：モックの 15/17/21px は提案値であり、既存の利用者設定を上書きしない（C05）。

## コントラスト実測（等倍・計算は sRGB 相対輝度）

テーマを切り替えて実測。`--nav-surface` が透過の edohigan / shinkai は不透明換算しない値のため参考。

| テーマ | 本文 / 紙面 | 補助 / 紙面 | 本文 / ナビ | 補助 / ナビ |
| --- | --- | --- | --- | --- |
| light | 16.56 | 5.26 | 14.75 | 4.69 |
| dark | 12.56 | 5.10 | 14.14 | 5.74 |
| yakou | 13.61 | 5.51 | 14.93 | 6.04 |
| shokou | 11.69 | 5.23 | 10.41 | 4.66 |
| edohigan | 12.02 | 5.69 | 12.83 | 6.07 |
| shinkai | 10.08 | 4.82 | 13.05 | 6.24 |
| crt | 11.59 | 4.92 | 11.26 | 4.78 |

C08の目標（通常文字4.5:1）に対する現時点の確認範囲は次のとおり。

- **紙面**：7テーマすべて、本文と補助文字を**CSSの実値から読んで**自動検査する（`themeContrast.test.ts`）。
- **ナビ面（不透明）**：light / dark / yakou / shokou / crt の5テーマを同じく自動検査する。
- **ナビ面（半透明）**：edohigan / shinkai は背景シェーダーを透かすため、宣言値では合成後を決められない。
  テストは「`rgba()` で宣言されていること」だけを固定し、コントラストは**実描画ピクセル**で確認する（下記）。

### 半透明ナビ面の実描画測定

設定ダイアログの左レール（`--nav-surface`）を等倍で描画し、その画素色とテーマの文字色から比を計算した。

| テーマ | レールの実描画色 | 本文 | 補助 |
| --- | --- | --- | --- |
| edohigan | `rgb(47, 30, 45)`（宣言 `rgba(46,29,44,0.78)` を紙面上に合成） | 12.67 | 6.00 |
| shinkai | `rgb(11, 40, 54)`（宣言 `rgba(9,36,49,0.78)` を紙面上に合成） | 12.46 | 5.96 |

**条件**：これは「ナビ面を紙面の上に置いた」合成での測定。アプリのサイドバーは背景シェーダーの上に載るため、
シェーダーの明るさによって合成色が変わり得る。ネイティブ実機での確認は未実施（UI-G受入の残項目）。

## 外部レビュー（G2/G3）への対応

P2×2と非ブロッキング指摘への対応。`2a118313` で実装側、本文書の更新で資料側を直した。

| 指摘 | 対応 |
| --- | --- |
| **P2: G2 最下部で最終カテゴリを current にできない** | `resolveSettingsCategoryIndex` に `viewport` を渡し、`scrollTop + clientHeight >= scrollHeight - 1` のとき最後の測定可能な見出しを返す。純関数テスト2件と、`scrollTop` を clamp する stub でのコンポーネントテスト1件を追加 |
| **P2: コントラストテストが実CSSを読まず、nav面が未検査** | テストを CSS の実値参照へ変更（`--text`/`--text-muted` をハードコードしない）。不透明ナビ5テーマを自動検査に追加。半透明2テーマは宣言形の固定＋本文書の実描画測定へ分離 |
| 半透明navの「全テーマ全面4.5:1」断定が強すぎる | 上記のとおり確認範囲を分けて書き直した。断定は「紙面と不透明ナビは自動検査済み、半透明は合成条件付きの実描画測定」まで |
| shokou の補助/紙面が古い値 | 表を `5.23` へ更新（`#526b7f` / `#f5f8fc`） |
| `chrome` をナビ面に寄せた判断 | **未決として記録**（下記） |

### 未決：chrome / tabs / status の面

現状は「サイドバー・上部ツールバー・ステータス＝`--nav-surface`、`.tabs-row`＝紙面」。
レビュー指摘のとおり、モックは上部バー・タブ・ステータスに `--bg`、サイドバーに `--side` を使う。
「chrome はナビ面」と正本に固定せず、次の役割分担を候補として残す。

| 役割 | 推奨 |
| --- | --- |
| Editor / Preview / Reader | `--surface-paper` |
| Sidebar / Settings rail | `--nav-surface` |
| Toolbar / tabs / status | `--bg`（将来 `--chrome-surface` を新設するならそこ） |

`.tabs-row` が既に紙面である等、現状は一貫していない。段階2（文字色・アクセント・境界線）と
同じスライスで決めるのがよさそうで、本文書では決定しない。

## 意図した差・未決

- **面の差は控えめ**：モックの紙面 `#fffefb` は白に近く、ナビ面も高明度。分離は明度ではなく色温度で作っている。
  もっと強く分けたい場合は、紙面の彩度かナビ面の緑みを上げる調整が要る（今回はモック値に忠実）。
- **開始画面の構造**：モック01は左＝ナビ面のヒーロー＋右＝紙面の一覧。**G3時点では未着手、G4で実装済み**
  （[G4](reviews/2026-09-10-v3-ui-g4/README.md)）。本文書の測定はG4前の開始画面に対するもの。
- **レール幅・アイコン・設定外枠の寸法**：`reviews/2026-09-10-v3-ui-g2/README.md` の未決を継続。
- **L Mode の紙と文字既定値**：モックの 15/17/21px と行間を既定へ入れるかは別決定（C05）。

UI-G の横断受入は未完了。UI-G合格・v3完成とはしない。
