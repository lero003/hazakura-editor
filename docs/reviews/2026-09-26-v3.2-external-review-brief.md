# v3.2.0 外部レビュー依頼（2026-09-26）

Status: Advisory / source候補を`main`へ統合済み、公開受け入れ未完了
Scope: v3.2固有の依存更新・品質修正・リファクタリングと公開ゲート

Hazakura EditorはmacOS向けのMarkdown-first Safe Editorです。Markdown/テキストsourceが正本で、Local AssistはDiffを示し、利用者が明示的にApplyしてUndoできます。v3.2のsource候補について、コード上の不具合・回帰リスクと、公開前に必要な証拠を第三者の視点でレビューしてください。**コードを`main`へ統合したことと、v3.2の公開を許可したことは別です。**

## レビュー対象の固定点

- v3.2固有のコード差分: [`f750576d`から`5ba2a9a6`まで](https://github.com/lero003/hazakura-editor/compare/f750576d747b06c1999638f3b425206d55828a03...5ba2a9a6eb11914c9b08d8c94f42ebc2e1c452fc)。前者はv3.2着手前の作業ブランチ先端、後者は統合後のコード・テスト先端。中心の実装commitは`aae05ce6`、CIテストの待機修正が`5ba2a9a6`です。旧`main`からの差分にはv3.1以前の87 commitも含まれるため、v3.2レビューにはこの固定差分を使ってください。
- sourceの製品版は`3.2.0`、App Store source設定の`bundleVersion`は`158`。最新のGitHub source tagは`v3.0.0`。v3.1のApple審査通過・公開はオーナー報告で、このレビューでは公開buildとsourceの対応を独立確認していません。
- 現在のコードは`main`へfast-forward統合・push済み。旧作業ブランチはローカル/リモートから削除済み。旧依存更新PR #46/#48/#49/#51は、同版以上を含む候補の統合後に重複更新として閉鎖されました。PR #52はGitHub上でマージ済みです。

## 何を変更したか

1. npm/Rustの依存を一括で更新。React 19.3、TypeScript 7.0.2、Vitest 5.0.2、Tauri 2.11.6、`ureq` 3.4.2、`pdf-extract` 0.12.1等を含みます。`@codemirror/view`は長い日本語原稿での表示回帰を実機評価するため**6.43.13をexact pin**。CIのNode 24と`@types/node` 24系列を維持し、SwiftPM Core AI runtime revisionはモデル/配布適合の別評価まで据え置きました。HTTPS画像取得の`ureq` 3移行、macOS向けネイティブ画面・helper buildも含みます。
2. 保存、外部変更監視、文字コード指定の開き直し、バックアップ一覧で、遅れたI/O応答が新しいタブ・入力・保存状態を上書きする競合を修正。メニュー/OS終了がAssist停止を待ち、待機中に生じた未保存編集を再確認するよう修正しました。
3. 大きくなった`AppShell`、`EditorPane`、PDF/HTML/EPUB書き出しから、L Mode復元、Assist候補レビュー、終了処理、編集コマンド/装飾、HTML生成、EPUBの章・リンク・目次・ZIPを責務ごとに抽出。source保存モデル、明示Apply、書き出し対象と画像許可の所有者は維持しています。
4. メモと縦書きの次期方針は文書化のみ。v3.2の実装・出荷機能として数えないでください。

詳細な変更と再現テストは`docs/releases/3.2.0-quality-hardening.md`、依存差分と実機受け入れ表は`docs/releases/3.2.0-dependency-acceptance-draft.md`。判断の正本は`docs/current-status.md`、製品の信頼境界は`docs/security-boundary.md`と`docs/assist-surface-strategy.md`です。

## レビュアーに求める判定

1. 固定コード差分にP0–P3の具体的な不具合や回帰リスクがあるか。あれば**ファイル・行・再現条件・影響・最小修正案**を示してください。特にI/Oの要求世代/React state競合、保存・dirty・Undo、Assist終了、L ModeとCodeMirror、PDF/HTML/EPUBの出力整合性を見てください。
2. 依存更新で画像URLのHTTPS/redirect/size制限、workspace path/symlink境界、App StoreとDeveloperの面の分離、Core AI pin、license/noticeに問題がないか。新機能の提案より、既存の信頼境界の破れを優先してください。
3. 自動テスト・CI・部分的な実操作と未実施ゲートを分けたとき、**v3.2のtag/署名配信/公開前に必須の修正と実機証拠**は何か。`main`統合を出荷承認とは扱わず、判断不能な点は「未確認」としてください。
