## R1 — 絵文字の後で一致強調がずれる

- Rust の `column` は **1始まりのコードポイント位置**（`search.rs`: `line.chars().position(...) + 1`）だが、
  UI は UTF-16 の `slice()` に渡していた。`😀余白` を「余白」で検索すると `\uD83D` の後ろから切り出す。
- 修正: 行の切り詰め（240文字）と着色の**両方**を `Array.from` のコードポイント単位へ統一
  （`toCodePoints()`）。`needle` の長さも同じ単位にした。
- 回帰テスト（`GlobalSearch.test.tsx`）: 絵文字の後・補助面漢字（𠮷）の後で、`mark` が一致2文字だけになり、
  **サロゲート片が混ざらない**ことを確認。

> テスト作成時、補助面漢字の `column` を3と書いて落ちた。正しくは5で、
> **UI 側の修正が効いていることを実測で確認できた**（誤った期待値は修正）。

## R2 — fit が25%未満だと「縮小」で拡大する

- 修正: `nextImageZoom` の縮小は、下の段が無いとき `IMAGE_ZOOM_MIN` ではなく**現在値を維持**する
  （`Math.min(current, IMAGE_ZOOM_MIN)`）。14.4% → 「−」で14.4%のまま。
- 回帰テスト: 6000×4000 を 1200×600 に fit（14.4%）→ 縮小しても増えないこと、段の中では1段落ちること。

## R3 — 縦長画像で fit が全体を収めない

- 修正: `fitImageZoom` から **5%の下限を撤去**（fit と手動倍率の下限を分離）。
  1000×20000 を 800×600 へ fit すると **2.88%**（表示は3%）で、高さが利用可能領域に収まる。
- 回帰テスト: `fit × 高さ ≤ 利用可能高さ`、`fit × 幅 ≤ 利用可能幅`、表示が `3%`。

## R4 — 読書進捗の「未計測」と ARIA の食い違い

- 修正: 計測済みかどうかを **章番号で判定**（既存の `measuredChapterIndexRef`。新しい state は足さない
  ——足すと計測経路の再描画が増え、既存の画像再計測テストを壊すことを実測で確認したため）。
- 未計測の間は **`aria-valuenow` を出さず**、`aria-valuetext`（「ページ数を数えています」）だけを出す。
- 計測済みは **`min=0 / max=総ページ / now=現在ページ+1`** にして、視覚の割合と ARIA の割合を一致させた
  （従来は `min=1 / now=1 / max=4` で、視覚25%に対し ARIA 上は0%相当だった）。
- 回帰テスト2件: 計測前は値を主張しないこと／計測後は視覚の塗り（25%）と ARIA の割合が一致すること。

## R5 — 生成案の上限を「入力対象が4,000文字超」と誤案内する

- 分類器（`classifyLocalAssistError`）で **`proposal exceeds the continuation limit` を `continuation` として分離**し、
  サイドバー側の理由も3つに分けた: `reasonSelectionTooLong`（入力対象）／`reasonProposalTooLong`（生成案）／
  `reasonContinuationLimit`（継続の上限）。それぞれの次の操作へ案内する文言を3言語で用意した。
- **誤ったまとめ方を固定していたテストを反転**（`reasonTooLong` 期待 → 3つの正しい期待）。
- 適用時の分類（`classifyApplyError`）も `continuation` を明示的に扱うようにした（既存文言は継続上限の説明
  だったため、そちらへ寄せてある）。
