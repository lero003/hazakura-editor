## R1 — P2: 電子書籍のキー処理がダイアログや他の操作部品から入力を奪う

**場所**: `src/components/editor/preview/EBookPane.tsx` の `isReaderPagingKey` / `handleCaptureKeyDown`（おおむね934–1042行）。関連: `src/hooks/app/useModalKeyboardGuard.ts`、`src/components/app/AppWorkspace.tsx` のサイドペインとリサイズ操作。

**問題**: `document` のcaptureリスナーで左右矢印・Spaceを拾い、ページを送り、最後に `article.focus()` している。入力欄、修飾キー、文字選択、Spaceでのボタン操作などは除外するが、「イベントが読書面の外から来た」「別ダイアログを操作している」「この読書面が非表示」という条件を除外していない。モーダル共通ガードの主な対象はEscapeとTabで、左右矢印はここで止まらない。

**再現手順**: 電子書籍サイドペインを開く → HTML書き出しを開く → キャンセルボタンにフォーカス → ArrowRight。

**抽出再現結果**: ページ送りカウンタが1増え、フォーカスが `cancel` から `reader` に移動した。入力欄にフォーカスした対照ケースではページ送りされなかった。実アプリでのページ番号・フォーカス位置の同時検証は未実施だが、ソースにはこの経路を防ぐ読書面外ガードがない。

**影響**: ダイアログ操作中に背後の読書位置が変わる。ペイン境界の左右矢印操作とも競合しうる。読書面を複数マウントしたまま一方を隠す経路も、同じガードの対象に含める。

**最小修正方針**: 開くときのフォーカス移動を明示し、ページ送りは表示中・アクティブな読書面が入力を所有している場合だけ実行する。モーダル表示中、読書面外、非表示/inert配下では処理しない。「とにかくdocument全体から読書面へフォーカスを戻す」方式をやめる。

**回帰テスト**: 読書面内の左右・Spaceは動く／書き出し・設定・バックアップのダイアログ中は動かない／ペイン境界の矢印で幅だけ変わる／非表示の読書面は処理しない／IMEと修飾キーを妨げない。

証跡: `reader-keyboard-repro.html`、`interaction-results.json`。

### 江戸彼岸: 「multiplyならコントラスト比が保たれる」は削除する

`docs/current-work.md` と第3弾レビュー資料には、紙と文字を同じ係数で暗くするためコントラスト比が保たれる、という説明がある。これは一般には成立しない。

コントラスト比は `(L明 + 0.05) / (L暗 + 0.05)` であり、同率の暗化でも比は一定ではない。さらにRGB値と相対輝度は同一の量ではない。したがってCSSにmultiplyとopacityが存在するテストは「指定が入っている」証拠にとどまり、合成後の文字の読みやすさを保証しない。

このレビューでは実アプリの合成結果が基準未達と測定したわけではない。**誤った保証を取り下げ、文字・薄い補助文字・選択範囲・リンク・ダイアログ上の合成結果を確認する**ことを求める。

### DPR: 上限を戻すことは無コストではない

実DPRが2以上で上限が効く場合、normalの1.5→2は描画ピクセル数の上限を約1.78倍、subtleの1.25→1.5は約1.44倍にする計算になる。これはフレーム時間が必ずその倍率になるという予測ではない。フレーム間引きを据え置いたことだけではGPU側の負荷が不変とは言えない。

確認するのは演出だけのFPSではなく、文字入力、スクロール、リサイズ、非アクティブ時、最小化・再表示、Reduce Motion時の振る舞い。M1等の実機で普段の文書を使って計測する。

## 実機受入の追加マトリクス

| 条件 | 受入基準 |
|---|---|
| 960×640・通常サイズ、長い文書名 | 書き出しの確定/キャンセル、設定/Help下端に到達できる |
| ja/en/kana・利用者が使う最大文字設定 | ラベル折返しで操作部が押し出されない。フォーカス表示を切らない |
| 拡大表示 | 実際に製品で提供/想定する拡大方法で確認。root fontを2倍にするfixtureをnativeの200%証跡と呼ばない |
| キーボードのみ | 検索→結果→実行、Tab/Shift+Tab、Escape、戻る先が一貫する |
| 電子書籍＋設定/書き出し/バックアップ | ダイアログ中は背後の読書位置も入力先も変わらない |
| 書き出しの遅い事前検査 | 枠が消えず、進行が分かり、キャンセル後に再出現しない |
| 初期状態・非対応・一時失敗 | ボタンが無効な理由と復帰手順が見える |
| 保存衝突・未保存・提案あり | 通常保存、比較、別名保存、キャンセルで情報を失わない |
| 読書: 画像読込後/最終ページ/見開き切替 | 欠け・飛び・位置の巻き戻りがなく、編集へ戻れる |
| 7テーマ・演出強度・Reduce Motion | 文書名・本文・警告・操作部の可読性と入力反応を維持する |
| native窓の状態遷移 | 信号機・ドラッグ領域・フルスクリーン・L Modeからの復帰が破綻しない |
| VoiceOver＋日本語IME | ラベルだけでなく、決定・取消・focus移動・変換確定が正しく機能する |

## 修正を渡すときの分割案

1. **書き出しセッション**: R2/R3/R6を一緒に扱う。外枠、キャンセル、形式切替のownerを揃え、既存I/Oと草稿契約を維持する。
2. **入力の所有権とactivation**: R1/R5。読書面外のキーを奪わず、ポインタ以外でも同じ操作が成立するようにする。
3. **小さなフォーム・状態表示**: R4/R7/R8。入力途中のdraft、初回保存、利用不可の説明を整える。
4. **演出の受入**: 誤ったコントラスト保証文を直し、native合成と性能を確認する。

各修正は対象SHAを明記して回帰テストと一緒に記録する。既存の2,433件が緑でも、完成値の一括入力、マウスのみ、通常長の名前だけでは今回の経路を通らない。既存テストが何を検証しているかの棚卸しと、今回の経路を通す統合テストを足すことが重要。
