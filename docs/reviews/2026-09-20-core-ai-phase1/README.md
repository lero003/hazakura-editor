# Core AI Phase 1 — 固定Qwen fixture配管

Status: Implemented and locally verified
Date: 2026-09-20
Scope: Developer / GitHub laneの固定test backend。C-1配布と本番モデル採用は対象外

> 後続の同日スライスで、固定fixtureとは別のCore AI production adapterと空catalog管理/選択を
> App Store / TestFlight buildへ追加した。この記録の「Core AI dependencyを含めない」は
> Phase 1時点の履歴であり、現在もtest model自体を配布しないという境界だけが継続する。

## 結論

固定Qwen3-0.6BをCore AIでロードし、既存の
`Local Assist → Proposal → Diff → 明示Apply → Undo`へ接続した。
生成直後のCancelと `system_default` への復帰も専用QA appで確認した。
候補品質は不合格であり、本番モデル採用・App Store同梱・公開準備の証拠にはしない。

## 境界

- Rust/nativeが `system_default` / `core_ai_test` と固定model pathを所有する。
- TypeScriptからbackend、path、任意model id、URLを入力できない。
- アプリはPython、変換、Hugging Face、download、network fallbackを起動しない。
- Core AI失敗時にSystemへfallbackせず、本文を変更しない。
- Phase 1時点の通常build / App Store buildはCore AI dependencyとtest modelを含めなかった。
  後続buildもtest modelは含めず、production adapterだけを空catalogで同梱する。
- Proposalは実応答の `modelId` を保持し、DiffにもSystem / Core AIを区別して表示する。

## 実機smoke

専用bundle idのDeveloper QA appと `/tmp` の一時workspaceを使用した。

1. `core_ai_test`でQwenをロードし、選択文への依頼を送信。
2. streaming後、Proposalをmain windowのDiffへ表示。
3. `Generated by: Core AI (Qwen3 0.6B test fixture)`を確認。
4. 明示Apply後に未保存となること、⌘Zで元文へ戻ることを確認。
5. 新しい会話で生成直後にCancelし、「文書は変更されていない」状態へ収束することを確認。
6. `system_default`で再起動し、System生成・Diff・`Generated by: Apple Intelligence`を確認。
7. Cancelでhelperを停止した直後に同じCore AI backendへ再依頼し、再spawn後もProposalまで到達。
8. Proposal保持中に対象本文を変更し、stale表示とApply無効化を確認。変更自体はUndoで戻した。
9. Local Assist窓だけを閉じ、本文・保存状態が変わらないことを確認。

Qwen候補は「今日は良い天気でず。」に対して「今日の良い天気でず。」で、校正品質は不合格。
System候補は同じ入力に「今日は良い天気だ。」。単回smokeの比較であり、品質bake-offではない。

## 失敗系の確認

- 実helperへmissing path、空directory、必要ファイル名だけを持つ壊れたbundleを順に渡し、
  `resource is missing` / `resource is invalid` / `model failed to load` を区別して返すことを確認。
- 実モデルへcontextを超える入力を渡し、`Core AI test generation failed`で終了することを確認。
  helperはcandidateだけを返す境界なので、失敗時に文書へ触る経路はない。
- Cancel直後の再生成、stale target、Local Assist窓closeは上記の専用QA appで確認。
- Phase 1のbackend選択はRustの起動時固定値で、実行中の切替UIを持たない。したがって
  「古いProposalを保持したままbackendを切り替える」状態は作れず、再起動時にin-memory Proposalも消える。
  Proposalに保存済みの`modelId`を表示時に上書きしない回帰はfrontend testで固定した。
- resource不整合の確認用に作った`/private/tmp` fixtureは確認後に削除した。
