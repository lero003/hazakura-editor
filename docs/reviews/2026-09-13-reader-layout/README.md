# 「読む」の見開き・文字サイズ・余白

Status: Verification record
Scope: v3 active-document Reader presentation and paging
Date: 2026-09-13

## 変更

- 起動ウィンドウは既定の1280×820のまま。目次と外余白を除いた読書領域で本文列を可変幅にし、標準サイズでも長文を見開きにする。
- 読書領域の見開き判定は800px。左右の本文間に52pxを取り、紙の外周余白も維持。狭幅は単ページ、短い最終章は一枚の紙という既存の振る舞いを維持。
- 読書の上部に「文字サイズ」を追加。12〜24で既存の `previewFontSize` を変更する。設定はプレビューと共通で保持し、エディタの文字サイズや原稿本文は変えない。
- 文字サイズ変更時は現在の概算source位置を使って改ページし直し、他の章のページ数キャッシュを無効化する。厳密な同一文字への位置保持ではない。
- コードブロックに重なっていた行単位の背景・罫線を解除。番号付きリストの字下げも文字サイズに追従させ、大きな文字で2桁の番号が切れないようにする。
- 可変幅の端数で2列を1列と誤判定し、ページ送りが倍になる計測を修正。末尾の丸めによる空ページも抑える。
- 実機確認で見つけた、目次の現在の章を押すとページ送りが待機したままになる既存不具合を修正。

## 検証

分離した macOS QA アプリと同梱の [sample.md](sample.md) を使用。ユーザーの原稿には手を加えていない。

- 既定サイズ・江戸彼岸: 修正前は単ページ、修正後は本文2列と中央余白を確認。
- 上部の文字サイズを15→24→15へ変更。24で再組版・ページ送り・2桁の番号表示を確認。QAアプリ再起動でも24を保持した。
- 最終ビルドで、現在の目次項目を押した後も標準幅では1→3ページ、狭幅では1→2ページへ進めた。
- ウィンドウを縮小して単ページへ切替、標準幅へ戻して見開きへ復帰。短い章は本文が欠けず一枚で表示。
- 「書く」へ戻って本文が未変更（保存無効）のままであること、再度「読む」へ入ってサイズ15を保持することを確認。
- 文字サイズによる再計測・概算位置保持、端数の列幅、現在章の目次再選択は red → green のテストで固定。
- 全 Vitest **282ファイル・2,498件成功**。`npm run typecheck`、最終QA build内の `npm run build:vite` 成功。
- App Store surface **125件成功**。最終QAアプリの ad-hoc 署名検証成功。`git diff --check` 成功。

既存の未コミット変更を含むQAアプリ。対象ソースと最終binaryのハッシュは [source-evidence.json](source-evidence.json)。
