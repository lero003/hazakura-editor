## 実装の内容

1. **左レール（既存の未コミット分を取り込み）**
   `@media (min-width: 800px) and (min-height: 481px)` で設定本文を1カラム化し、
   カテゴリナビを左180pxの縦レールにする。テーマカードは4列。
2. **現在地の導出**（`src/components/app/settingsCategoryRail.ts`）
   ナビは本文を該当見出しへ送るだけの入口で、独立した選択状態を持たない。
   現在地は本文のスクロール位置から導出する（UI-A0 の「表示選択は既存状態から導出する」方針）。
   各見出しの上端が読み位置（本文上端＋80px）を越えている最後のカテゴリを現在地とする。
3. **表示**：`aria-current="true"` を現在地のボタンに付与。レールでは `--accent-soft` の
   淡い塗り＋左端2pxの `--accent` バー、狭幅・低い有効領域の横並びナビでは `--accent` の枠線＋塗り。
   枠線と左バーの二重線は避け、左端は1本にした。

### 引き継ぎ時に見つけて直した不具合

未コミットのCSSだけでは「押しても現在地が残らない」状態だった。原因は2つ重なっていた。

- `scroll` 直後の `getBoundingClientRect()` が位置確定前の値を返す場合がある。
  → 測定を `requestAnimationFrame` の次のフレームへ移した。
- カテゴリ押下時の移動は見出し上端の16px手前を狙うが、フォント読込や折返しの変化で
  着地が数十pxずれる（実測で最大71px）。読み位置24pxでは押した項目が現在地から外れ、
  押下直後の `scroll` が1つ手前のカテゴリへ巻き戻していた。
  → 読み位置を80pxにし、着地のずれを吸収する。

再現は `src/components/app/SettingsCategoryRail.test.tsx` の
「keeps the clicked category after the scroll it caused settles」で固定した。

### 全7テーマの実描画測定

fixtureのスクリーンショット（960×640、等倍）から画素を採取し、sRGB相対輝度で比を算出。
現在地ボタンの塗り・左バー・本文のレール背景を、それぞれ最頻色で比較した。

| Theme | ラベル文字 / 現在地の塗り | 左バー / レール背景 | 塗り / レール背景 |
| --- | --- | --- | --- |
| light | 14.88 | 5.78 | 1.03 |
| dark | 12.28 | 8.36 | 1.08 |
| yakou | 13.67 | 6.32 | 1.01 |
| shokou | 10.07 | 4.16 | 1.09 |
| edohigan | 11.06 | 6.94 | 1.06 |
| shinkai | 10.08 | 8.05 | 1.11 |
| crt | 10.59 | 10.20 | 1.06 |

本文の4.5:1目標は全テーマで満たす。重要なUIの3:1は**左バーが担う**（最小4.16）。
塗りだけの差は1.0〜1.1で、意図的に淡い（面ではなく位置とバーで示す）。
`edohigan` / `shinkai` のレール背景は半透明のため、実描画の画素で測った。
