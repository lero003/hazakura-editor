## 一緒に進めたUI-B2

開始画面は紹介と実際の再開操作を二列にし、文書列幅1050px以下で縦積み。
空のworkspaceだけsidebar・下段chromeをCSSで隠す。既存workspaceではsidebarを残す。
フォルダを開く、新規、ファイルを開くの順とし、再開候補がある場合は再開へ、
ない場合はフォルダ操作へ初期フォーカスを置く。最近の項目・下書き復旧の実データと操作を継続する。
画像に架空の履歴や日時は追加していない。

えるモードは本文上余白104pxを64–88px、下余白156pxを96px、行高1.78を2.05へ。
先頭H1を2.5emから1.95emへ、H2を1.65emから1.35emへ抑え、左寄せ・下線なしにした。
既存の本文幅720px・水平余白・source chip領域を維持。
H1の通常行とH3以下の既存装飾、Editorの実装、タイプライター、保存とUndoの所有者は変更していない。
書体や行間の新設定、Assist内部再編は今回に含まない。

## 確認したこと

ローカル実行の証跡。GitHub CI成功としては扱わない。

| 段 | 結果 |
| --- | --- |
| frontend | 239ファイル、2,089テスト成功（前回2,081 + 修正6 + UI-B2 2） |
| App Store表示境界 | 111テスト成功 |
| typecheck / Vite build | 成功 |
| App Store preview build | ローカルad-hoc app生成成功。提出・公証・配布受入ではない |
| diff | diff --check成功 |

フロント全体テスト後、開始画面の縦積み閾値だけ900pxから1050pxへ調整し、
960px画面を再撮影、typecheck/Viteとnative previewを再ビルドした。
既存の見出し中央寄せテストは新しいH2左寄せ仕様へ更新。source chipの水平安全幅テストは保持。

ブラウザーの実アプリUIを操作し、以下を確認した。

1. 960×640で既存下段Previewを閉じてから開くと、Editorはdisplay:none、Previewはflex。
   「書く」で反転する。横方向のページoverflowなし。1440pxでは両方flexに戻る。
2. かなふみで同じ入口を操作し、新groupと2ボタンのかな表記・Preview表示を確認。
3. 開始画面1440×850 / 960×640で操作と復旧項目を確認。960pxで主要操作が画面内に収まる。
   実際に検証用下書きを復元して編集面へ戻った。OSのファイル選択ダイアログは今回未追試。
4. えるモード960pxで本文幅720px、上余白64px、15px文字の行高30.75px。
   1440pxも撮影。タイプライターをON/OFFし、末尾に試験文字を入力、通常編集へ戻ってUndoで取り消した。

今回のnative実操作、IME変換、VoiceOver仮想カーソル、200%表示、全テーマは未確認。
前回の22px/24pxブラウザー試験を新しいL Modeの拡大試験へ流用しない。
Reader背景sidebarのVoiceOver確認もUI-Gで継続。UI-B全体の受入完了ではない。
