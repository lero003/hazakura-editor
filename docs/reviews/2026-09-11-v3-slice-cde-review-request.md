## 1. 特に見てほしい点（実装側の自己申告リスク）

1. **江戸彼岸の明色化**（`edohigan-theme.css` / `lMode.css` / `EdohiganShaderOverlay.tsx`）
   - モックが定義するテーマは `:root`・`.dark`・`.edohigan` の3つだけで、**モックの江戸彼岸は明色**
     （紙 `#fffcf8` / 地 `#fbf4f2` / インク `#453735` / アクセント `#975b68`）。実アプリは暗色だった。
   - **モックの罫線値（`#e6d8d0` 1.36 / `#c9b6ae` 1.90）は既存の階層契約（1.45〜1.7 / ≥2.1）を満たさない**ため、
     色相を保って `#dccac0`(1.55) / `#bfa8a0`(2.20) へ置き直した（B案の前例に従う意図的な差）。
   - えるモードの暗色グループから edohigan を外し、**机 `#fbf4f2` の上に紙 `#fffcf8`**という構造にした
     （モック03の紙はライトテーマの紙で、「えるモードはテーマの紙を使う」という構造に合わせた）。
   - **シェーダーは加算から「桜色へ寄せる」方式へ変更**（明色では加算が白飛びする）。花びらは左右の余白のみ。
     **WebGL の中身はヘッドレスで撮影できない**ため、装飾の見た目は実機の目視が未受入。
   - 前景オーバーレイの z を `--z-crt-top`(1200) → `--z-base`(1) へ下げ、**モーダル/パレットより手前へ出ない**
     ようにした（モック20の要求）。
   - **えるモードの分割バー**が窓の約38%を `--border` で覆っていた既存不具合を修正
     （1440×850 で323px。ライトテーマでも同色帯で出ていた = テーマ非依存）。

2. **画面14（保存衝突）の版カード**
   - ディスク側は**本文を読まず** `get_file_metadata` のバイト数と最終更新だけを出す
     （文字数は本文を読まないと分からないため**出さない**）。読めない場合は数字を出さない。
   - 読み取りは新しいフック `useDiskFileMetadata` に分離（読み取り専用・pathless/非Tauri では何もしない・
     遅延応答は破棄）。**保存・比較・戻るの経路は既存のまま**（上書きへ進むボタンは置いていない）。
   - `.close-dialog` の `max-width: 420px` を上書きするためセレクタを一段強くしている
     （`.save-conflict-backdrop .save-conflict-dialog`）。**この上書きの是非**を見てほしい。

3. **画面24（画像プレビュー）の倍率**
   - **100% = 画像1px が CSS1px**（devicePixelRatio では変えない）。**fit は 100% と別物**で、
     小さい画像は 1 を上限に拡大しない。表示変換のみ（再圧縮・保存なし）。
   - 拡大時は `overflow: auto` + `place-items: safe center` で端へ到達できる。
   - **実機での巨大・破損・透明・不在・権限案内は未確認**。

4. **画面07の挙動変更（意図的）**
   - 反映後は**反映ボタンを消し**、「文書へ反映しました（未保存）。⌘Zで戻せます。」へ置き換える
     （同じ案をもう一度「採用」させない）。既存テストの期待を**反転**させた：
     「反映後も Applied ボタンがある」→「反映後はボタンが消える」。この判断の妥当性を見てほしい。
   - 追加・削除の凡例を追加（記号は `DiffBody` と同じ `-` / `+`）。
   - **本文面化（右下フローティング→本文領域）は未実装**のまま（別スライス相当）。

5. **画面22の失敗表示**
   - 別窓の未知エラーは**生の内部文字列を出さない**（3言語）。既存テストの期待を反転させた。
   - サイドバーは内部メッセージを `classifyLocalAssistError` で分類し、**理由別の短い案内**を出す。
   - 「もう一度試す」は**既存の送信経路**（`submit()`）を呼ぶだけで、新しい生成経路を作っていない。

6. **検索の wire 形式変更（要確認）**
   - Rust の `WorkspaceSearchResult` に **`total_files_matched` を追加**した（走査数とは別）。
     TS 側の型・hook・表示を同時に更新しているが、**他にこの構造体を読む経路がないか**を確認してほしい。
   - 一致の着色は backend の `column`（1始まり・文字位置）を使い、**query は trim して長さを揃えている**。

7. **書き出しのラベル変更（ユーザー可視）**
   - EPUB/PDF の主操作を「書き出す」→「**書き出し先を選ぶ**」へ統一（HTML と揃えた）。
   - HTML に「「本全体」は PDF と EPUB で書き出せます（HTMLは1文書ずつ）。」を追加。
   - **形式ナビの統合（1モーダル化）は未実装**（3コマンド分離のまま。D02 は native 別窓の新設を必須としていない）。
