## 結論

基調は揃っている。全面的に作り直す必要はない。淡いナビ面、温かい紙色、緑の主操作、明朝の読む面は通常編集・えるモード・ダーク・江戸彼岸まで続いている。

直す効果が大きいのは **設定／ヘルプの案内、復旧／衝突の面色、検索結果の密度、読書の章見出し**。**960px前後の2分割**は既存の判断待ちを再検討したい。モックにない機能を足すことや、ボタン数・装飾の完全一致は勧めない。

[モックと現行を並べた比較レポート](report.html)に、指摘と24画面の対応・撮影画像を掲載。

## 優先する修正候補

### F1・中: 設定／ヘルプで案内の調子が変わる（15〜18）

設定は左に日本語のカテゴリがある一方、その上に全幅の **Settings / Help → Settings** が常時並ぶ。ヘルプへ移ると左レールが消え、英語の技術文書と公開文案についての注記になる。モック18は「書く・読む・整える・届ける」の短い日本語の案内だった。色よりも、ここで「日常の文章道具」から「技術資料を読む画面」へ切り替わる差が大きい。

**最小案:** 既存の設定／ヘルプ切替を自然な日本語へ揃え、設定の目次と上部切替の役割を整理する。初めて使う人向けの短い日本語の入口を置き、詳細な開示文書はそこから辿れるようにする。新しい24画面ルートや設定永続化は不要。後半の入口新設はモック18の未採用部分なので、採用判断と実装を分ける。

これはfixture固有の英語表示ではない。`PreferencesDialog.tsx:73` の固定文言と `PrivacyPreferencesPane.tsx` の英語専用表示、および `AppOverlays.tsx:618` の本体接続を確認。

証拠: `15-appearance.png`, `16-typography.png`, `17-assist-settings.png`, `18-help.png`。

### F2・中: 復旧／衝突だけ半透明の灰色に戻る（13・14）

設定と書き出しは不透明な紙面だが、復旧と保存衝突は全面が灰色に沈み、内側の白いカードだけ浮く。モック14は外側を暗くしても、判断するダイアログ自体は白い紙として保っている。危険操作の場で、他の面より古い別系統のダイアログに見える。

**最小案:** 対象のダイアログ本体を既存の `--surface-paper` に揃える。警告・選択・フォーカスの区別と、背景を暗くする処理は保つ。共通 `.close-dialog` を一括変更する前に利用面を確認する。

根拠: `src/styles/dialogs.css:15` の `rgba(..., 0.85)`。設定は同ファイル29行目から `--surface-paper`。復旧は `RestoreFromBackupDialog.tsx:70` が共通クラスを利用。

証拠: `13-recovery.png`, `14-conflict.png`。合成後の全テーマの文字コントラストは別途測定が必要。

### F3・中: 検索結果がコマンド一覧の密度になる（09）

見出し・検索欄に比べ、結果の行とファイル区切りが極端に小さい。13pxの等幅文字、薄い余白、濃緑の選択帯がまとまり、文章を探す面というよりパレットの候補一覧に見える。モック09の本質は専用ページであること以上に「ファイル名→文章の抜粋」をゆっくり読める階層にある。

**最小案:** モーダルのまま、ファイル見出し／結果行の上下余白を増やし、抜粋の書体と行間を本文寄りにする。選択を淡い面＋明確な印へ寄せる場合もキーボード現在地を弱めない。検索方式や索引を追加する必要はない。

根拠: `src/styles/global-search.css:110`（13px・等幅・padding 5px 14px）、同135行目の全面accent選択。

証拠: `09-search.png`。現行の結果数が少ないことによる窓の低さそのものは欠陥として扱わない。

### F4・中: 読書の章見出しが扉ページのように強い（04）

常設目次と紙の外の下部操作帯は、今回の変更でモックの方向へ近づいた。残る差は紙の内側。章の先頭が中央寄せ・太字・飾り線・大きな下余白になり、左右の章頭が同時に見えると見出しが2つの主役になる。モックは左寄せの穏やかな組版で、本文へ自然に視線が流れる。

**最小案:** 先頭見出しを本文の左端へ揃え、太さ・飾り線・下余白を一段抑える。本文サイズの保存済み設定、ページ計測、現在位置を維持する。柱・ノンブルや架空の章メタ情報を追加する必要はない。左右の紙の境目を弱く示す案は後段の好み調整。

根拠: `src/styles/preview.css:1387`〜1429の先頭見出しと疑似要素。章を跨ぐ右ページプレビュー自体の是非は今回の指摘に含めない。

証拠: `04-reader.png`。組版変更はページ数が変わり得るので、再計測・章移動・狭幅を確認して採用する。

### F5・判断待ち: 960pxでも2分割が続き、余白を失う（23）

960×640、サイドバーを畳んだ状態でも編集とPreviewが並ぶ。通常幅での紙面の広さに対し、両方の行が短くなり、同じ静けさを保ちにくい。モック23はこの領域を単一の読む面へ切り替えていた。

**最小案:** 960〜1024付近で単一ペインを優先するか再検討する。窓幅だけでなく各ペインに残る本文幅で判断したい。既存の780pxコンテナ閾値と保存済み分割比の復帰を確認する。単一表示を希望しない利用者もいるため、単純にモック値へ合わせる修正にはしない。

既知事項 `docs/v3-mock-gap-inventory.md` のAを今回960pxでも再確認したもの。新しい回帰の指摘ではない。

証拠: `23-compact-edit.png`。根拠: `src/styles/workspace-paper.css` のcompact条件。

## 再現と次の一手

Habitatを実行し、依存追加不要・npmを利用する方針を確認。`npm run dev:vite` で現在のソースを起動し、Codexのin-app browserで操作・撮影した。`app.html` はこのレビュー用ブラウザoriginだけにテーマと表示設定を指定する。本番アプリの設定やファイルは変更しない。

アプリの機能コード／CSSは未変更。追加はレビュー資料・撮影画像・表示fixtureのみ。`git diff --check` と作業ツリー確認を実行。機能修正ではないためVitest／typecheck／配布ビルドは実行しておらず、過去の成功件数を今回の結果にはしていない。

次に着手するなら **F2の面色 → F3の結果行 → F4の組版** を別々の小さなスライスで確認する。F1は固定英語の解消と使い方の入口を分け、後者とF5は採用判断として扱う。残る12/21/22と06の会話あり状態は、同じ候補.appで実際の抽出／生成／停止／失敗を起こして見比べる。
