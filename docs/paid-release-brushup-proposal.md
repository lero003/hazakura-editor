# ¥2,000で売るためのブラッシュアップ提案

Status: Proposal — 未着手・オーナー判断待ち
Scope: Hazakura Editorを「¥2,000の買い切りアプリ」として売るために必要な小さな改善の棚卸しと優先順位
Authority: Advisory（製品方針・価格・配布の正本を上書きしない）
Last reviewed: 2026-10-21

## 0. 前提

- 対象は **Hazakura Editor 本体**（現行 source 3.4.0）と解釈した。
- **価格・販売地域・契約・税務はオーナー判断**（App Store Connect）。この文書は価格を確定せず、Connect固有情報も書かない。
- 現状: 公開 v3.2.1（2026-10-14オーナー報告）、v3.3は審査提出済み（2026-10-19オーナー報告）、sourceは3.4.0。
  テーマ刷新S0〜S10はcommit済み（2026-10-21）。既存の署名pkgはS10前のため再生成が必要で、実機受入は未完了。
- **¥2,000の根拠は、リポジトリ内にまだ存在しない。** 唯一の価格候補は海外向け **US$4.99買い切り**の提案（未承認、[海外販売ガイド](international-launch/README.md)）。v0.5期には¥500帯で「無料で使うには十分、課金するには惜しい」と結論していた記録がある。つまり¥2,000は、過去に検討した価格の数倍へ跳ぶ前提であり、**機能を1つ足して埋まる差ではない**。競合比較・支払意思の分析も docs には無い。
- この文書は提案のみ。第10章の判断が決まってから1スライスずつ進める。

## 1. 診断 — いまのままだと¥2,000が難しい理由

¥2,000（買い切り）は、無料側（Obsidian、VS Code、CotEditor、Apple Notes）と有料側（Typora・Marked 2級）の境目にある。この帯では「機能数」ではなく **最初の10分で価値が伝わるか** と **失敗したときに壊れないか** が値段の根拠になる。現状の弱点は6つ。

1. **深いのに、深さが売り場にも初回にも出ていない。** 実装は「書く（L Mode）→ 本として読む（Reader・見開き）→ EPUB/PDF/HTMLへ出す → 差分で整える」まで揃っている。しかし開始画面（`src/components/workspace/StartPanel.tsx`）は「静かに書き始める」「書いて、読んで、確かめる。」＋「フォルダを開く／新規ファイル／ファイルを開く／最近開いたフォルダ／復旧候補」だけで、この流れを一件も示さない（初回はサイドバーとタブ行も隠れ、保存と書き出しは無効）。さらに2回目以降は前回のワークスペースとタブが自動復帰するため、**開始画面はほとんど再表示されない**。初回導線をここだけに置くと1回で消える。購入者が10分でReaderと書き出しに辿り着かなければ、¥2,000の価値は体験されないまま終わる。
2. **主コピーの後半（ローカルAIで整える）が、まだ証明されておらず、初期状態では到達もできない。** E4B v1の日本語崩れはhelper生出力で再現したまま未解決、E4B v2はローカル `.aar` 作成済みでも配布catalogは `not_published`、8,000字の文脈では両モデルとも生成エラー、12Bは16GB実機でタイムアウト報告。加えて `assistSurfacePreference` の初期値が `"none"` のため、**新規インストール直後はLocal Assistをどこからも開けず、設定で有効にしても再起動が必要**。**「AIで整える」を¥2,000の購入理由の前面に置くのは、現時点では危険**。これは[海外販売ガイド](international-launch/README.md)の「AIだけを購入理由にしない」とも一致する。
3. **日本語の「使い方」が無い。** アプリ内Helpは英語のみ（`src/components/app/helpDocs/en/`、2026-06-09のオーナー判断）で、内容もPrivacy・OSS・診断・ローカルデータ開示が中心。**書き方・読み方・書き出し方を日本語で説明する文書が無い。** 2026-09-11の画面棚卸しでは「18 使い方」面が未実装として挙がっており、以後の解消記録も見当たらない（要確認）。
4. **買う前の情報が機能一覧になりやすい。** Mac App Storeの有料アプリは体験版を出せないため、ストアページが唯一の「試用面」になる（※仕組みの最終確認は要）。スクリーンショットと副題で「書く／読む／届ける」が伝わるかが購入判断をほぼ決める。
5. **失敗時の見え方が価格に直結する。** 保存衝突・外部変更・文字コード・AI利用不可の説明が粗いと「¥2,000でこれは無い」になる。ここは作り込まれているが、**署名候補での実機受け入れが残っている**。公開Privacyと実装の食い違い（任意のリモート画像・Core AI）も未訂正で、信頼面の穴になっている。
6. **残る受け入れがIME・Retina・VoiceOver・Intel・macOS 26 GUI。** IMEと表示品質は日本語話者の体感そのもの。未検証のまま値段を上げると、レビューで最初に突かれる。

## 2. 提案の骨格

| # | 柱 | ねらい | 主な担当 |
|---|---|---|---|
| A | 最初の10分 | 買った直後に「書く→読む→届ける」を1回体験させる | 開発（小） |
| B | 毎日の執筆 | 日本語の入力・組版・状態表示で不満を出さない | 開発（中） |
| C | 読む・書き出す | 「元を取った」と思える出力品質を実機で保証する | 開発（中） |
| D | 買う前に伝わる | ストアとWebで価値が3秒で伝わる | オーナー＋素材提供 |
| E | 失敗とAIの誠実さ | 失敗の説明・復帰導線・AIの立ち位置を正直にする | 開発（小〜中） |
| F | 受け入れ | 未検証項目を署名候補で閉じる | 開発（実機） |

**推奨の重心はA。** 機能を足すより、既にある深さを最初の10分に露出させるほうが、同じ工数で値段の説得力が上がる。AIは「整える」を主役にせず、条件付きの追加価値に置く。

## 3. A群 — 最初の10分（いま足すと効く最小の新規）

| ID | やること | なぜ¥2,000に効くか | 規模 |
|---|---|---|---|
| A-1 | **同梱サンプル原稿**を開始画面から1クリックで開けるようにする。骨格は既存の `book-like` ひな形（4章＋index＋notes、`src/features/okf/scaffoldTemplates/assets/book-like/`）を土台にし、本文だけサンプル用に書き下ろす（2〜3ページ） | 初回に「本として読む」「EPUBへ出す」を30秒で体験できる。既存の開始画面に入口が無い。素材の再利用で新規構造を作らずに済む | S |
| A-2 | **初回だけの3行ガイド**（えるモード＝読み書きの見た目／本として読む／書き出し）。設定から再表示でき、コマンドパレットとHelpからも常時たどれるようにする | 深い機能の存在に気づける。えるモードやBook Scopeの用語説明はHelp（英語・法務中心）に見当たらない。開始画面は2回目以降ほぼ出ないため常設の入口も要る | S |
| A-3 | 価値コピーに「本として読む」「書き出す」を足す（現行は `startValuePitch: "書いて、読んで、確かめる。"`／`src/lib/locale/safeEditor.ts`） | 購入理由の上位2つ（本として読む・EPUB/PDFへ出す）が最初の画面の文言に無い | S |
| A-4 | **「はじめかた」1枚**をHelpへ追加（日本語・操作手順のみ。法務文書とは分ける） | Helpが英語＋法務中心で、書き方の説明が無い。未実装の「使い方」面の代替にもなる | S〜M |
| A-5 | 空状態の文言統一（ワークスペース未選択／タブ0／検索0件／Reader対象なし） | 「次に何をすればいいか」が分からない状態を無くす | S |
| A-6 | 書き出しとReaderの入口を開始画面から1段深く辿れるようにする（サンプルを開いた後の案内） | A-1で開いた原稿から「本として読む」「書き出す」へ自然に渡す | S |
| A-7 | Local Assistへの導線を初回ガイドに1行入れる（**既定値は変えない**。有効化は設定＋再起動であることを明示し、同意した人だけが進む） | 現状は新規インストール直後にどこからも開けず、主コピーの「AIで整える」を体験できない。既定を黙って変えると信頼境界に触れるため、案内で解決する | S |
| A-8 | EPUB/PDF/HTMLで**できないこと**（HTMLは現在ファイルのみ、PDFはA4固定・余白プリセットのみ、EPUBは書誌と表紙と範囲のみ）をpreflightとHelpに明記 | 期待値のずれは返金・低評価に直結する。できることより先に限界を示す | S |

A-2〜A-8は既存のi18n（ja／kana／en）へ載せる。**A-4は2026-06-09の「Helpは英語のみ」判断を一部見直す提案**であり、採用可否はオーナー判断。
A-1のサンプルは同梱物を読み取り専用で開くだけにし、起動時に利用者のフォルダへ自動で書き込まない（OKFひな形の明示操作とは入口を分ける）。

## 4. B群 — 毎日の執筆（日本語品質）

| ID | やること | なぜ効くか | 規模 |
|---|---|---|---|
| B-1 | **IME実機受入**（長文日本語・変換中・折り返し・カーソル・L Mode） | 日本語話者は入力の気持ちよさで値段を判断する。署名候補のGUIと実CodeMirrorでは未確認 | 実機 |
| B-2 | 編集面の約物調整（`palt`・`text-spacing-trim`・`line-break`）。読み面はv3.4 S2で適用済み、編集面は禁則のみ | 原稿の見た目がそのまま商品価値。B-1の後 | S〜M |
| B-3 | **実機の入力・スクロール・テーマ負荷の基準値**を記録し、退行を検知できるようにする | `scripts/measure-markdown-render.mjs` はjsdomのパースのみで「WebKit paint、editor latency、scrolling、theme costは測らない」と明記している | M |
| B-4 | 検索・置換の使い勝手（ヒット数、大文字小文字、全置換の確認とUndo） | 「無い」と「分かりにくい」は同じ不満になる | S |
| B-5 | 保存まわりの状態語彙を統一（保存済み／未保存／外部変更／競合／バックアップ／復元） | 状態の意味が揺れると保存が信用されない | S |
| B-6 | キーボードだけで主要導線（focus可視、Escape、タブ・ペイン移動） | 有料エディタの基本作法 | S〜M |
| B-7 | 200%文字・狭幅・最大文字サイズでの破綻修正 | 拡大して使う層の離脱を防ぐ。未確認項目 | S |
| B-8 | 期待される小物の棚卸し（全角/半角、スペルチェック、行番号など）と、無い物はHelpで明示 | 「無い」ことの説明が無いと不満として残る | S |
| B-9 | タブの重複名・オーバーフロー・配置の整理 | 長く使うほど効く。v1.13系の残項目 | S |

| ID | やること | なぜ効くか | 規模 |

| E-1 | 保存衝突・外部変更・復元・バックアップの文言と導線の通し確認 | 保存の信頼が価格の下限を決める | S |

## 9. 推奨する進め方

**第0段（作業ではなく判断）**: ¥2,000の根拠を「書く・読む・届ける」に置くと決める。AIは条件付きの追加価値に下げる（D-2／E-6）。

**第1波（¥2,000の前提を作る）**
1. F-1のうちIME・F-2のRetina（B-1の受入を兼ねる）
2. A-1 サンプル原稿、A-2 初回ガイド、A-7 AIへの導線、A-8 書き出しの限界明記
3. D-1／D-2／D-6 の素材と訂正
4. E-1／E-3 の通し確認

**第2波（体感を上げる）**: B-2 編集面の組版 → B-3 実機性能の基準値 → C-1〜C-3 書き出しとReaderの実機受入

**第3波（磨く）**: B-4〜B-9、A-3〜A-6、C-4／C-5、E-2／E-4／E-5、D-3〜D-5

**次版**: 縦書き（C-6）、見直しメモ・再開メモ（採用済み・未実装）、AI品質の再評価

各スライスは1回で検証できる単位に切り、`npm run typecheck`／`npm test`／`npm run build:vite`、UIは`npm run smoke:app-store-surface`と実機smokeを通す。実装前にはHazakura Habitatを実行し、AGENTS.mdの境界（実行・path・AI・自動適用を増やさない）を確認する。

## 10. 決めてほしいこと

1. **価格と地域**（Connect操作。日本が現在無料なら、有料化の告知方法と既存利用者への説明を先に決める）
2. **AIの立ち位置**: ¥2,000の購入理由の前面に出すか、条件付きの追加価値に下げるか（推奨: 下げる。F-9を通せたら戻す）。あわせて、初期状態で到達できない点を**案内で補うか、初回に有効化を促すか**（既定値そのものは変えない提案）
3. **A-4（日本語の「はじめかた」）**を採用するか（2026-06-09の「Helpは英語のみ」判断の一部見直し）
4. **第1波の着手順**（推奨: IME・Retinaの実機受入 → A-1／A-2）
5. 縦書きを今回の¥2,000に含めるか、次版へ送るか（推奨: 次版）

## 11. やらないこと

- 新機能（メモ・縦書き）を¥2,000の条件にしない。版割りが未定で、価格の前提にすると遅延要因になる
- AI品質が未証明のまま「ローカルAIで整える」を主コピーの前面に出す
- IDE化・Git・LSP・汎用ターミナル・拡張基盤（AGENTS.mdの境界を維持）
- 価格変更のためだけにサブスク／IAPを新設しない
- 「一切通信しない」「完全オフライン」など実装を超える主張（リモート画像の明示許可経路がある）
