## 前回の追加削減 — 2026-10-14、基準 `25f21528`

オーナーの追加依頼は、比較可能な受け入れ試験を広めに行い、リスクが過大でない候補を
できるだけ減らし、問題のある変更だけを戻せるようにすること。依存数だけを採否の根拠にしない。
新しい製品機能・trust boundary・任意実行・自動適用は加えない。

| 候補 | 採用する変更と残す契約 | 交換条件・留保 |

### 個別撤回

採用を機能ごとに分け、候補の問題に対応するcommitだけを `git revert` する。
実装HEAD `f4588002` の同じ状態から、別の一時cloneで各変更を一つだけ撤回して照合した。
4件は競合なし。platformとURLSessionは下記一箇所の文脈競合を解決し、他の採用を維持した。
全6件で両macOS targetのlocked/offline metadata、npm manifest/lock整合、notice再生成が通過。
URLSessionだけ戻した状態とPDFKitだけ戻した状態は、arm64の `cargo check --locked --offline --lib` も通過した。
復帰後の全アプリの実操作試験を完了したという意味ではない。

| 単位 | commit / 撤回対象 |
|---|---|
| npm dialog adapter | `76ad3b6e`。公式npm packageの宣言・入口・lock・関連testを戻す |
| 共通native build処理 | `b401d3a3`。既存bridge buildの整理。通常は個別native変更の撤回時に残す |
| Tauri platform defaults | `8211351d`。manifest/lockのplatform指定だけを戻す |
| Foundation feature限定 | `1ded08fe`。Foundationのfeature宣言だけを戻す |
| compression無効化 | `806ca68f`。compressionと対応lockを戻す |
| URLSession | `af4b604d`。ureq、画像transport、専用native bridge/build呼出しを戻す |
| in-process PDFKit | `f4588002`。pdf-extract、PDF抽出、専用native bridge/build呼出しを戻す |

| 撤回した単位 | 復帰後のmacOS Cargo解決集合 | 留保 |
|---|---:|---|
| npm dialog | 254 | npm runtimeは33件へ戻る |
| platform defaults | 257 | 下記のmanifest解決が必要 |
| Foundation feature | 254 | 競合なし |
| compression | 258 | 競合なし |
| URLSession | 267 | 下記のbuild.rs解決が必要 |
| PDFKit | 281 | 競合なし。旧parserの既知panicも戻る |

cleanな作業treeから `git revert --no-commit <対象SHA>` を実行する。
`8211351d` のCargo.toml競合は、圧縮無効のままplatform featureだけ再有効化して解決する:

```toml
tauri = { version = "2", default-features = false, features = ["wry", "dynamic-acl", "common-controls-v6", "x11", "dbus"] }
```

`af4b604d` のbuild.rs競合は、remote_image呼出しとそのcfgだけを除き、PDFKit呼出しを残す:

```rust
    #[cfg(target_os = "macos")]
    build_background_assets_bridge();
    #[cfg(target_os = "macos")]
    build_foundation_bridge("pdf_text", &["Foundation", "PDFKit"]);
    tauri_build::build();
```

解決した該当fileを `git add` し、noticeを再生成・stageした後に撤回commitを作る。
他の撤回も同じようにnoticeを再生成してからcommitする。これは上記最終組合せから一件だけ戻す手順。
複数撤回や後続変更ではmanifestの現行featureも照合し、無関係な設定を上書きしない。
基準前の背景効果 `25f21528` は今回の個別復帰試験に含めていない。現在の組合せからの単純revertでは
Cargoの競合があるため、必要になった場合は直接window-vibrancyとlockの復帰を別に検証する。

依存を戻した後はnoticeを再生成し、対象面の試験と両lane buildを行う。
source原稿と保存形式のmigrationはない。新native APIの境界と例外処理は独自保守範囲として残る。
全面revertを前提にせず、圧縮の容量増、特定PDFの抽出差、特定HTTPS環境の失敗を別々に判断する。

## PDFの初期判断 — 二経路を維持

選択ロジックの読解基準は `5e3310aa`。比較には既存live PDFKit helperと
`pdf-extract 0.12.1` の既存rlibを使い、自作PDF7件を一時領域で測った。
初回の既存binaryのビルド元commitは独立未照合。後続のこの作業でlive PDFKit helperを
現行sourceから再buildし、7件すべてのtext抽出responseが初回と一致することを確認した。
Rust比較runnerは既存rlibのまま。新規依存・個人資料は使用しない。
Rust runnerは既存rlibを `rustc --extern pdf_extract=… -L dependency=…` でリンクした。
日本語fixtureは埋込ToUnicode fontを使った単純な文書。入力7件の前後SHA-256一致を確認。

| 英語1頁 | 語句・順序保持、score 672 | 語句保持・空行増、score 674 | Rust |
| 日本語1頁 | 語句・句読点保持、score 886 | 語句保持・空行増、score 888 | Rust |
| 日英混在3頁・中央空頁 | 3頁・順序・空頁保持、score 1716 | 全語句保持、頁境界と空頁が潰れ1頁、score 720 | PDFKit |
| 空1頁 | 空 | 空 | OCRへ進む |

| 暗号化 | 1頁の空text | password error | Rust errorを返す |
| 不正PDF | 読込error | xref parse error | Rust errorを返す |

最終列は経路別の実測へsourceの選択ロジックを適用した推定。
アプリ全体の取込pipelineは実行していない。scoreは空行数でも変わるため、勝者を品質の正解としない。
Rustは実際に選ばれる経路で、helper不在・起動失敗・fixture-only・非macOSでも使われる。
PDFKitの正常系が通っただけでは除去を採用できない。

OCRはこのエージェントの実行sandbox内で `Failed to create CVPixelBuffer`。
sandbox外の一度の再確認もscanが実験の30秒上限で終了し、空PDFは再試行していない。
製品の120秒watchdogを検証した結果ではなく、OCR成功・製品の不具合のどちらも確定しない。
App Sandbox内のstage・取消・原稿保全、CID/特殊encoding/複雑な読順は未確認。
一時fixtureにはOS fontを埋めたため、そのまま配布testへ昇格させない。

再開条件は、再配布可能fontの恒久fixture、有効PDFのhelper不在成功test、OCRが動くホスト、
同一候補のsandbox取込を固定すること。score・fallback・分岐の改善は別スライスで扱う。
この判断で依存初期評価を閉じ、PDF削除をメモ・縦書きの前提にしない。

## 追加 — macOS背景効果をTauriへ集約（基準 `995df92c`）

オーナーの追加試行依頼に基づき、`lib.rs` の一か所を `WebviewWindow::set_effects` へ移した。

依存の自前実装や背景効果の削除ではない。

- `Sidebar`、`Active`、radius未指定、main不在時return、失敗時も起動を継続する契約を維持する。
