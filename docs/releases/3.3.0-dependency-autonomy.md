Status: Review candidate

Authority: Operational

## PDFの初期判断 — 二経路を維持

選択ロジックの読解基準は `5e3310aa`。比較には既存live PDFKit helperと
`pdf-extract 0.12.1` の既存rlibを使い、自作PDF7件を一時領域で測った。
初回の既存binaryのビルド元commitは独立未照合。後続のこの作業でlive PDFKit helperを
現行sourceから再buildし、7件すべてのtext抽出responseが初回と一致することを確認した。
Rust比較runnerは既存rlibのまま。新規依存・個人資料は使用しない。
Rust runnerは既存rlibを `rustc --extern pdf_extract=… -L dependency=…` でリンクした。
日本語fixtureは埋込ToUnicode fontを使った単純な文書。入力7件の前後SHA-256一致を確認。

| 自作PDF | PDFKit | Rust | 現行scoreによる選択・分岐の推定 |
|---|---|---|---|
| 英語1頁 | 語句・順序保持、score 672 | 語句保持・空行増、score 674 | Rust |
| 日本語1頁 | 語句・句読点保持、score 886 | 語句保持・空行増、score 888 | Rust |
| 日英混在3頁・中央空頁 | 3頁・順序・空頁保持、score 1716 | 全語句保持、頁境界と空頁が潰れ1頁、score 720 | PDFKit |
| 空1頁 | 空 | 空 | OCRへ進む |
| 画像だけのscan | 空 | 空 | OCRへ進む |
| 暗号化 | 1頁の空text | password error | Rust errorを返す |
| 不正PDF | 読込error | xref parse error | Rust errorを返す |

最終列は経路別の実測へsourceの選択ロジックを適用した推定。
アプリ全体の取込pipelineは実行していない。scoreは空行数でも変わるため、勝者を品質の正解としない。
Rustは実際に選ばれる経路で、helper不在・起動失敗・fixture-only・非macOSでも使われる。
PDFKitの正常系が通っただけでは除去を採用できない。

OCRはこのエージェントの実行sandbox内で `Failed to create CVPixelBuffer`。
sandbox外の一度の再確認もscanが実験の30秒上限で終了し、空PDFは再試行していない。
製品の120秒watchdogを検証した結果ではなく、OCR成功・製品の不具合のどちらも確定しない。
App Sandbox内のstage・取消・原稿保全、CID/特殊encoding/複雑な読順は未確認。
一時fixtureにはOS fontを埋めたため、そのまま配布testへ昇格させない。

再開条件は、再配布可能fontの恒久fixture、有効PDFのhelper不在成功test、OCRが動くホスト、
同一候補のsandbox取込を固定すること。score・fallback・分岐の改善は別スライスで扱う。
この判断で依存初期評価を閉じ、PDF削除をメモ・縦書きの前提にしない。

- 直接宣言と型専用分類、view pin、残存lock metadata、language/lint経路を確認する。

  Read-only/Assist-lock、Diff→Apply→Undo、保存・衝突、VoiceOverを受け入れる。
- 署名候補、TestFlight、App Store公開は未実施。既存3.2.1の公開報告をv3.3の受け入れに流用しない。
