## この版の位置づけ

`3.1.0`は開発中の次版。現時点では、Local Assistの表示整理と、英語表示・読み上げに
関わる言語境界、致命的エラーからの復旧面を改善している。Markdown / テキストsourceを
正本とし、生成結果をDiffで確認してから明示的に採用する契約は変えていない。

この文書は早期草案であり、署名済み候補、TestFlight提出、App Store申請、公開の証跡ではない。
Core AIのE4B catalog・Apple-hosted取得コードは内部TestFlight受入用に接続したが、`.aar`生成・
Apple upload・実機取得、品質採用、海外App Storeの設定、署名候補での英語受け入れは未完了。
完了していない機能は掲載文へ含めない。

Local Assistの画面を見直し、対象範囲と依頼候補をすばやく確認できるようにしました。

## 現時点で実装済みの変更

### Local Assist

- 対象文書・選択範囲の要約を短くし、依頼候補をチップとして選べる構成へ整理した。
- 冗長な説明を減らし、依頼入力・モデル表示・送信操作を一つの入力面へまとめた。
- 送信ボタンを生成中は停止ボタンへ切り替え、停止処理中は重複操作を防ぐ。
- Local Assist窓でモデル選択枠を開き、入手済み・検証済みのモデルを切り替える契約を接続した。
- 設定にCore AIモデル管理面を追加し、内部TestFlight用E4Bのdownload、進捗、取消、再開、削除、
  再起動後の復元をApple-hosted asset packへ接続した。未検証payloadは選択できない。
- 生成結果は従来どおり本体のDiffへ送り、採用前に確認する。自動保存・自動反映は行わない。

### 言語表示と復旧

- メイン窓とLocal Assist窓の表示言語をHTMLの言語情報へ反映し、初回描画前にも保存値を適用する。
- UIの言語を本文へ誤って継承させず、表やraw HTMLに明示された本文言語を保持する。
- 英語UIで致命的エラーが起きたときの復旧画面を英語化し、`null`や`false`が投げられた場合も
  復旧操作へ進めるようにした。

## TestFlight / 審査で確認すること（草案）

**最初に通す一本:** 文書を開く → Local Assistを開く → 依頼候補を選ぶ → 送信 →
生成中に停止 → 同じ窓から再依頼 → 完了した提案を本体Diffで確認 → 反映 → Undo。

- 停止要求後、片方の処理だけが先に完了しても操作ロックを維持し、両方の完了後に再依頼できる。
- 停止した古い生成結果が、次の依頼やDiffへ遅れて採用されない。
- モデル選択枠はApple Intelligenceと、download・検証済みの場合だけGemma 4 E4Bを選択可能にする。
- 設定でE4Bのdownload、進捗、取消、再開、検証、削除、再取得を確認し、任意URL/path入力を出さない。
- 日本語IMEの変換確定で依頼を誤送信せず、停止後に入力へ戻れる。
- VoiceOverで対象、依頼候補、入力、モデル選択、送信／停止、Diffへの移動を判別できる。
- 英語表示で致命的エラーの復旧面が英語になり、再読み込み操作へ到達できる。
- Local Assistの提案を破棄した場合と、採用後にUndoした場合のどちらもsourceを安全に戻せる。
