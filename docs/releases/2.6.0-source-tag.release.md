# Hazakura Editor 2.6.0 Source / Local App Release

Status: Source-preview candidate prepared; tag and publication pending
Scope: v2.6 Local Assist conversation + Diff review
Authority: Medium
Last reviewed: 2026-08-16

`2.6.0` is the current source candidate at commit `b40bd217`. The v2.6
implementation is merged on `main`, but this note does not claim a source tag,
App Store package, TestFlight upload, App Review, GitHub Release, or physical
device validation. Those are separate gates.

## What changed

- Local Assist now keeps conversation input separate from the current unapplied
  proposal. Follow-up instructions revise the same pinned document target and
  replace the current Diff proposal.
- The editor buffer remains unchanged during generation. Only an explicit Diff
  Apply action can create the existing `AiEditTransaction` / Review Bar entry;
  Apply does not invoke generation again and does not auto-save.
- The detached Assist window keeps conversation and Diff review as separate
  regions, including a narrow-width layout that preserves the two-column Diff
  and wraps the change summary below `520px`.
- Diff column headers are exposed to the accessibility tree and cells are
  associated with Original / Proposal. Visual line numbers remain hidden from
  assistive technology.
- Cancellation is reported separately from failure, and availability shows a
  checking state until the on-device probe settles.

## Release boundary

This is a source-only / local-app candidate. It does not attach a DMG or an App
Store package. Hazakura Local Assist remains a preview, on-device writing
companion with no network fallback, background rewriting, auto-save, tool
calling, workspace-wide indexing, or autonomous apply. Core AI model catalog and
download work are outside this release.

Build locally with:

```bash
npm ci
npm run build
```

The generated app is a local validation artifact. It is ad-hoc signed and not
Developer ID signed or notarized.

## Known limits and remaining gates

- Detached-window narrow widths, keyboard/focus order, spoken VoiceOver,
  streaming summary verbosity, real streaming/cancel, and available/unavailable
  Foundation Models behavior still require physical macOS confirmation.
- The existing non-blocking A-3 hardening ideas (completion-time target text
  revalidation, Diff failure/no-op Apply gating, and an Apply status watchdog)
  remain follow-up work and do not change the explicit-Apply boundary.
- A source tag, App Store/TestFlight package, App Review, and GitHub Release
  require a separate explicit approval and evidence pass.
