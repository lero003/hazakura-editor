## 調査結果と修正

オーナーから簡単な実機テストでは問題がなかったとの報告を受け、通常操作では
出にくいI/O応答の遅延・逆転とReactの状態更新の競合を検証した。
この報告だけでIME・VoiceOver・署名済みTestFlightの個別ゲートを完了にはしない。

| 対象 | 再現した問題 | 修正 |
|---|---|---|
| 外部変更監視 | 古い読込結果が保存完了後の本文を巻き戻す。同じパスを開き直した別セッションに古い結果・エラーが付く。重複チェックが新しい衝突情報を消す。 | セッション・保存基準・衝突判断とチェック世代を完了時に照合。保存中は開始せず、状態更新の内部でも再確認する。入力中の本文・文字コード・改行は保護して衝突を通知する。 |
| ディスクから開き直す | 読込待ちの間に保存しても、古い内容またはエラーで新状態を置き換える。文字コードを連続指定すると先に完了した古い指定が残る。 | 保存基準と本文・形式を照合し、最新の要求だけ反映する。同じReact batchに入った入力も保護する。 |
| 通常保存の失敗 | 保存待ちのタブを閉じ、同じパスを開くと、以前の保存エラー・衝突表示が新タブに付く。 | 成功時と同様に失敗時もセッションを照合する。 |
| 自動バックアップ一覧 | 原稿を切り替えて一覧を開き直すと、古い成功・失敗・終了通知が新しい一覧や読込中表示を上書きする。 | 一覧要求の世代を照合し、開始時に旧一覧を消す。workspace対象外・未選択への変更とunmountでも古い要求を無効にする。 |
| アプリ終了 | 未保存変更がないとメニュー終了がAssist停止を待たない。OS終了では停止待ちの間に別タブが編集されても終了する。 | メニュー・OS終了ともAssist停止後に最新タブの未保存状態を再確認し、変更があれば終了を中断して確認ダイアログへ戻す。 |

保存基準の照合を `src/features/editor/documentIoBaseline.ts` に集約した。
保存済み表示が次の入力でidleになる遷移は、保存基準の変更と区別する。
自動監視と明示的な開き直しは、`flushSync` 内の状態更新でも照合し、
未反映の入力・保存・閉じる処理を見落とさず、その結果に合わせてステータスを表示する。

## 責務の整理

依存関係を増やさず、既存の生成処理と操作の所有者を分離した。
行数は責務を移した元ファイルの比較であり、アプリ全体のコード量や速度の改善を意味しない。

| 元ファイル | 整理前 → 後 | 分離した責務 |
|---|---:|---|
| `useDocumentExport.ts` | 1,333 → 942行 | PDF/HTMLの自己完結HTML生成、テーマ変数の列挙 |
| `epubExport.ts` | 1,500 → 788行 | stored ZIP、章分割・本文直列化、収録リンク変換、目次の構築と直列化 |
| `EditorPane.tsx` | 1,892 → 1,478行 | 書式・表・インデントの編集コマンド、テーマ・検索・不可視文字の装飾 |
| `useAppShellController.ts` | 2,293 → 1,952行 | L Modeへの出入りとpane復元、Local Assistの候補レビュー・破棄確認、終了とセッション保存 |

EditorPaneのライフサイクルとimperative APIは作業開始時の本文と一致することを照合。
移した編集・装飾の14関数、EPUBの21関数、Local Assistの操作callback、
L Modeのcallback/effectも抽出前と照合した。L Modeは参照状態をbooleanと表示文言で受ける。
書き出しの対象選択・画像の許可・保存ダイアログ・キャンセルは元のhookが引き続き所有する。

## 残る受け入れ

修正後アプリの実機操作、IME、VoiceOver、署名済みTestFlightは未実施。
公開ゲートは [v3.2受け入れマトリクス](3.2.0-dependency-acceptance-draft.md)を維持する。
とくに使い捨て原稿で次を確認する。

1. 外部編集→アプリへ戻る、入力→保存、衝突→「編集を続ける」→再確認。
2. 保存や開き直しの直前・直後のタブ切替、同じファイルを閉じて開く操作。
3. 文字コード指定の開き直しと入力の競合、改行設定だけが未保存のときの外部変更。
4. バックアップ一覧を閉じ、別原稿で開き直し、Diff確認→明示反映→Undo。
5. L Modeの出入りと右pane復元、日本語選択の書式変更→Undo、Assist生成中の編集ロック。
6. 単一原稿/Book ScopeのPDF・HTML・EPUB出力と、章・目次・章間リンク・画像の確認。
7. Assist生成中のアプリ終了、終了準備中に別タブを編集した場合の確認ダイアログ。

依存更新・計画文書等とあわせて`main`に統合した。この品質強化では
依存・配布設定・保存先の権限境界・自動保存/自動適用を追加していない。
リポジトリ全体の網羅監査や、v3.2の公開受け入れ完了を意味しない。
