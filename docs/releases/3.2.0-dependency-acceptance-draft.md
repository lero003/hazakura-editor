# v3.2.0 依存関係更新・実機受け入れドラフト

Status: Draft / 候補未受け入れ
Scope: v3.2.0の依存更新と同一候補の受け入れ
Authority: Advisory（境界は `docs/security-boundary.md`、公開判定は `docs/current-status.md`）
Last reviewed: 2026-09-26

## 主題と範囲

v3.1公開後の次版を **v3.2.0「依存関係の更新」** とする。新しいLLM機能や
MLX runtimeの追加は今回の主題に含めない。npmとRustの直接依存を原則一度の版に
まとめ、メジャー更新は一件ずつコンパイル・テストしてから同じ候補へ統合する。
最終判定は**同一ビルド**のmacOS実機操作で行う。sourceテスト、ローカルの
アプリ起動、署名済みTestFlightの受け入れは別々に記録する。
sourceの製品版番号は3.2.0候補、App Store source設定の`bundleVersion`は158。
公開済みbuildとの照合と提出候補の採番・署名・配信は別ゲートとする。

| npm開発依存 | TypeScript 7.0.2、Vitest 5.0.2、jsdom 30.1.1、Vite 8.3.1等 | CIのNode 24とローカルNode 22で`npm ci`、型検査、全テスト |
| Rust | Tauri 2.11.6、dialog 2.7.3、pdf-extract 0.12.1、ureq 3.4.2、window-vibrancy 0.8.1等 | 二重リンク、PDF、HTTPS画像、ネイティブ画面 |
| CodeMirror view | 6.43.13をexact pin。旧6.43.2からの更新は**実機ゲート必須** | 長い日本語原稿、折り返し、カーソル、L Mode、IME |
| `@types/node` | Node 24系列の24.13.6に更新。26系列は採らない | CIのNode 24と型定義を合わせる |
| SwiftPM Core AI | 配布モデルと結び付いたrevision pinは維持 | runtime更新はモデル形式・生成・配布の別評価が必要 |

`cargo update`で互換範囲に残る古い推移依存は、上流の版制約に従う。
`npm outdated --json`の直接依存で残るのは、CIのNode 24に合わせて
据え置いた`@types/node` 26系列だけ（2026-09-25確認）。

上表は9月25日のローカル候補と旧PRの比較。9月26日に同版以上を含むv3.2候補を
`main`へ統合・pushし、4件のPRは重複更新として閉鎖された。個々のPRを
そのままマージしたという意味ではない。

CIのNode 24は[Node.jsのLTS](https://nodejs.org/en/about/previous-releases)にある。
Node 26は現時点でCurrentで、今回のビルドに必要な改善は見つかっていないため、
CIのNodeと`@types/node`を24系列で揃える。ローカル検証はNode 22で行った。
`main`のv3.2候補に対しQuality Actionsを実行した。初回
[run 36234429617](https://github.com/lero003/hazakura-editor/actions/runs/36234429617)は
native成功、frontendの非同期通知テスト1件のみ失敗。通知を待つよう修正した
`5ba2a9a6`の[再実行](https://github.com/lero003/hazakura-editor/actions/runs/36234798000)は
frontend・nativeとも成功。CIはクリーンなNode 24/Linux・macOS 26での再現性を確認するゲートであり、
IMEや表示などの実機受け入れとは分ける。

SwiftPMの据え置きは「新版で動かない」と確認した結果ではない。2026-09-25時点で
現在のpinから上流HEADまで`apple/coreai-models`は12 commit（Swift推論エンジンを含む）、
`john-rocky/coreai-kit`は145 commit（runtime・catalog等を含む）の差がある。
helperのコンパイルだけでは既存の配布モデル、取得、生成、署名済み配布での適合を
判定できないため、v3.2ではrevision pinを維持し、更新は別のモデル互換性評価とする。

`@codemirror/view` 6.43.3付近でHazakuraが経験した行消失・カーソルずれは、
[CodeMirror公式変更履歴](https://codemirror.net/docs/changelog/)に後続の
tile-tree修正があるだけでは解消を断定できない。候補を実操作で評価し、再現するなら
この依存だけ6.43.2へ戻して原因を記録する。

macOS 27と現行Rustでrelease proc-macroの`LINKEDIT`配置が不正になる事例は
[Rustの既知問題](https://github.com/rust-lang/rust/issues/157750)と同じ症状。
Cargoの`release.build-override`でビルド時だけdebug情報とcodegen単位を調整する。
出荷するアプリ本体のrelease最適化には適用しない。

## 自動ゲート

1. `npm ci`、`npm run typecheck`、`npm test`、`npm run build:vite`、
   `npm run smoke:app-store-surface`。
2. App StoreとDeveloperの両方のVite入力・Tauri bundleを確認する。
   `npm run build`はad-hocのApp Storeプレビューで、署名済み提出物ではない。
3. `cargo fmt --manifest-path src-tauri/Cargo.toml -- --check`、
   `cargo test --locked --manifest-path src-tauri/Cargo.toml`、
   `cargo audit --file src-tauri/Cargo.lock`、`npm audit`。
4. Swift helperの出力アーキテクチャ、同梱、起動、Diffの明示反映・Undoを確認する。
5. `git diff --check`と配布文言のパス・秘密情報衛生を確認する。

監査結果は実行時点の既知advisoryだけを示す。`cargo audit`の保守・unsound警告は
脆弱性0件と分けてトリアージする。

## 実機受け入れマトリクス（部分実施）

使い捨てworkspaceと同一のv3.2候補を使い、各行にOS・CPU・メモリ・候補build・
結果を記録する。失敗したらその画面と入力、再現手順を残す。

| 面 | 実操作と合格条件 |
|---|---|
| 通常編集 / CodeMirror | 見出し・表・コードフェンス・日本語の長文を開き、折り返しONで先頭・中ほど・末尾へ移動。入力、複数行選択、検索、Undo/Redo、保存後のsource一致。行の消失・空白領域・カーソルずれがない。 |
| L Mode / IME | 同じ原稿でL Modeを数回切り替え、かな漢字変換中に入力・選択・改行・スクロールする。未確定文字を失わず、切替後も表示とsourceが一致する。 |
| Preview / export | Markdown中の表・リンク・画像・HTMLをPreview、Reader、PDF、EPUBで確認。HTMLのsanitizeとリンクのOS受け渡しを維持する。 |
| HTTPS画像 | 設定OFFでは通信しない。明示ONのHTTPS画像は表示、redirectは拒否、非画像と上限超過は失敗表示。保存済み原稿を勝手に変更しない。 |
| ファイル / dialog | 開く・保存・Save As・衝突・復元、PDF/画像Import、Book Scopeの章切替と書き出し。キャンセル時にsourceを保つ。 |
| Local Assist | 利用できるSystem/選択済みローカルモデルで提案→Diff→明示Apply→Undoと停止を確認。Core AIのApple-hosted取得は署名済みTestFlightで別途確認する。 |
| ネイティブ画面 | macOS画面でウィンドウのvibrancy、テーマ、狭幅、スクロール、対話のフォーカスを確認。Developer laneではAgent Workbenchの境界も確認。 |
| アクセシビリティ | キーボード操作、Escape、VoiceOverの主要ラベル、文字サイズや表示倍率を確認。 |

macOS 26/27、Apple Silicon/Intelの対応範囲で実施できない組み合わせは
「未実施」と記し、別環境で補う。自動テストやad-hocプレビューから
TestFlight・Apple審査・公開の合格を推定しない。
現時点ではIMEの未確定入力、VoiceOver、画像の非画像応答・上限超過、
PDF最終ページの表示と画像入りPDF、ファイル衝突・復元、Local Assistの
Diff→Apply→Undo、署名済みTestFlightのAssist/Background Assets、
macOS 26/Intelの操作を受け入れていない。提出時はnotice同梱と
Swift側ライセンス本文を同じ署名済み候補で再確認する。
