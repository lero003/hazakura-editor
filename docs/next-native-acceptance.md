# 第二世代：第一世代との比較・実機受け入れ

Status: 手順のみ。実機未実施。配布判定書ではない。
Scope: 同じMacと合成原稿での比較、第二世代の安全契約、測定と判定の記録
Authority: 手順の正本。実装・検証済みの範囲は[現状](current-status.md#第二世代--macosネイティブ再構築)、着手順は[作業キュー](current-work.md#active-queue)。

## 準備：アプリと原稿を混ぜない

1. 第一世代はオーナーが選んだ既存のアプリ（製品版または候補）を使い、版・ビルド・配布レーンを記録する。比較のために第一世代をビルドし直したり、設定や復旧記録を消したりしない。第二世代は専用ブランチのコミットを記録し、[開発用アプリの手順](../next/README.md#ビルドテスト起動)で作る。アドホック署名の開発用アプリと署名済み候補の挙動は同一扱いにしない。
2. 原稿を持たない検証用macOSアカウントで行う。いつもの設定・ワークスペース・復旧領域は参照・共有しない。同期外のローカル領域を使用し、アプリが用意できない世代や隔離できない試験は「未測定」とする。強制終了はそのアカウントの試験対象アプリだけに限る。
3. リポジトリのルートで次を実行する。表示された新規ディレクトリの `first/` は第一世代、`next/` は第二世代専用。同名ファイルは生成直後にバイト一致する。どちらかを編集した試験の後は、必要に応じて再生成した一組を使う。Git管理下のファイル、日常の原稿、両世代共通の保存先は使わない。

   ```bash
   swift next/scripts/make-acceptance-fixtures.swift
   ```

   | 原稿 | 見るもの |
   |---|---|
   | `01-reading.md` / `02-reading.md` | 日本語・結合文字・絵文字、同名の「窓辺」、両原稿の末尾近くの「桜のしおり」、最後の短い段落 |
   | `03-encoding.txt` | UTF-16BE BOM、CR・LF・CRLFの混在、末尾改行なし |
   | `04-long.md` | 編集・計測専用の長い日本語行。最後の行「長文の終点」。プレビュー・出力の比較には使わない |

## 操作と合格条件

両世代で結果を別々に記録する。UIや機能の差ではなく、共通の目的を比較する。第二世代の手順・期待結果は下表のとおり。第一世代で同じ操作に当たらないものは [実機スモーク](smoke-checklist.md)から相当する操作を選び、なければ「対象外」にする。

| ID | 操作 | 第二世代の期待結果 |
|---|---|---|
| E1 | `01` と `02` を開き、編集用コピーを作る。日本語IMEで変換途中にタブ切替や終了を試す。変換を確定する回と取り消す回を作り、タブ往復後にUndo/Redo。結合文字・絵文字を含む範囲も選ぶ。 | 未確定入力を原文に取り込まない。変換中にタブを失わず、確定後は各タブの本文・選択・Undo履歴を保持する。 |
| S1 | `03` の編集用コピーを一度も編集せず、新しい名前で保存。保存パネルでの取消と、別に用意した既存名への保存も試す。 | 新規保存のバイト列が原本と一致（`cmp`）。取消・既存名の指定では書き込まず、原本・既存の保存物・編集用タブを維持する。 |
| S2 | `01` の編集中コピーを開いたまま、外部から試験用の同じファイルにだけ追記。「原本の版を比較…」で再選択し、比較表示後に同一ファイルへもう一度追記。「比較時のディスク版を別タブで開く」を押して編集タブに戻る。 | 開いた時点・比較時・手元の編集版を区別する。参照タブは1回目の追記までを表示し、編集タブ・最新の原本を書き換えない。外部ツールがファイルを置換したら同一ファイルと判定しないため、同一ファイルへの追記でやり直す。 |
| S3 | 「フォルダの原稿一覧…」で `next/` を選ぶ。1件を選び、フォルダ再選択を取り消す回、別のフォルダを選ぶ回、同じフォルダを選ぶ回を分ける。 | 取消・不一致でタブを増やさず、同じフォルダの照合に成功した場合だけ1件を読み取り専用で開く。ピッカー後に元のウィンドウへ戻れる。 |
| S4 | 未保存の合成原稿を編集し、通常の閉じる／終了で破棄確認を取り消す。別の回で固有の試験文を確定し、少なくとも3秒待って試験アプリだけを強制終了する。再起動後に「原稿を復元」を開く。 | 取消では原稿が残る。復元した確定文は入力と一致し、元の復旧記録は自動削除されない。退避済みと確認できた確定文が欠落・不一致、または復元不能なら不合格。 |
| R1 | `01` の目次から2つの「窓辺」を選び分ける。全文／章表示を切り替え、「桜のしおり」を検索し、末尾を表示して検索を閉じる。同じ版で開き直し、原文行へ戻る。`01` と `02` の読書画面でも横断検索する。 | 同名・章・原稿の区別と一致順が正しく、末尾や選んだ原文行へ移動できる。Esc後に編集へ戻れ、原文は変わらない。リンク先は開かない。 |
| R2 | `01` からHTML／PDF／EPUBを書き出す。各形式で新規保存・取消・既存名を試す。複数原稿のEPUBも、`01` → `02` のタブ順で作る。既存の閲覧アプリで日本語、末尾、EPUBの目次と読み順を確認する。 | 取消・既存名では書き込まない。新規ファイルだけが生成される。第二世代PDFは縦長1ページの試作で、用紙ごとの改ページとは区別する。 |
| R3 | 狭いウィンドウと通常幅で、えるモード・集中表示・外観を切り替える。集中表示は `⌘⇧J` とTabで終了ボタンに移動してSpaceの両方を試す。編集・プレビュー・差分の可読性とVoiceOverの読上げを確認する。 | 本文・選択・Undoを保ち、操作後に編集へ戻れる。読み取り専用・復旧などの通知が分かり、ライト・ダークからシステム設定へ戻せる。第一世代の装飾との一致は求めない。 |
| A1 | 別バンドルの合成候補採用デモでEsc取消、明示採用、Undo、採用差分シートの開閉、再起動を試す。推論の可用性・時間は別CLIの `--check`／`--compare` で記録する。 | 取消で原稿は変わらず、採用は選択範囲だけに一度反映される。Undoしても採用時点の差分は変わらず、デモ終了で消える。CLIが使えない環境は「未測定」とし、採用デモの成功を推論品質・停止・メモリの根拠にしない。 |

S1・R2の取消には未使用名を指定し、確定せずに閉じた後もその名前にファイルがないことを確認する。既存名の試行には、新規保存・出力に使った名前とは別の、同じ拡張子で明らかに異なる内容の合成ファイルを用意する。第二世代自身の上書き拒否を調べる回は、その使い捨てファイルに限りOSの置換確認が出たら先へ進み、拒否の表示と前後のハッシュ一致を確認する。OSのダイアログだけで止まった回は、アプリによる拒否とは区別して記録する。

保存・出力の試験では、他の操作や外部追記を混ぜずに原本と既存宛先の前後ハッシュを確認する。S2の外部追記は例外で、2回目の追記後と比較操作後のハッシュを照合する。開発用アプリのピッカー試験をOSサンドボックスの検証として扱わない。

待ち時間だけではS4の退避完了の証拠にならない。稼働中のタブは復旧一覧に出ないため、失敗時に完了の証拠がない回は「未測定」とし、確定した時刻・待機秒数・退避警告の有無と復旧一覧の結果を残す。復元が成功しても、電源断や未確定入力を復元できるとは判断しない。

## 性能比較と記録

- 同じMac・OS・表示倍率・ウィンドウサイズ・入力ソース・電源条件で、同時に起動せず比較する。版／コミット、ビルド構成（配布ビルドか開発ビルドか）、テーマ、原稿のサイズとSHA-256を残す。比較条件が違う場合は数値を記録しても優劣を断定しない。
- **起動:** アプリを通常終了した状態から、起動操作→主ウィンドウで入力できるまで。ビルド時間は含めない。OSのキャッシュ状態は制御しない。起動時のサンプルや復旧状態も揃えるか、違いを記録する。
- **長文:** 各回、未編集の `04-long.md` から編集可能なタブを開き直し、通常表示・先頭行・選択なしから始める。ウィンドウ幅を900 ptから550 ptに変え、操作を終えてから折り返しとカーソル表示が安定するまでを記録する。共通の幅を取れない場合は測定前に両世代で取れる幅を決め、実測値を併記する。次に `⌘↓` で末尾へ移動し、「長文の終点」が表示されるまでを測る。最終行末尾で日本語IMEの「はるのしおり」を入力して「春のしおり」に変換し、確定キーを押してから確定文が表示されるまでを記録する。途中で操作方法が異なった場合は記録して数値を直接比較しない。各回の編集は保存しない。編集用コピー作成は計測に含めず、読込時間を測るなら「ファイル選択 → 表示」を別欄にする。
- **メモリ:** 同じ長文操作を終え、操作せず10秒待った時点をアクティビティモニタで記録する。アプリ本体と、そのアプリに帰属を確認できる補助プロセスを分けて記録する。帰属不明のものを含む合算値は出さない。
- 同じ方法で世代ごとに5回測り、中央値・最小・最大と、入力やスクロールの引っかかりを残す。時計または録画の精度も記録する。計測がない行は「未測定」であり、性能改善の主張には使わない。

記録は `試験ID | 世代・ビルド | 合格 / 不合格 / 未測定 / 対象外 | 観測結果と再現手順` を基本とし、共有時にローカルパスやアカウント情報を含めない。

## 判定

- データ消失、無断上書き、取消後の書込み、退避済み原稿の復元不能、選択や承認なしの採用を再現した場合は置き換え不可。再現原稿・操作と、保存前後のバイト比較を添えて修正を優先する。安全契約に未測定の項目があれば、置き換えの安全判定は保留する。
- 第二世代の未実装と不具合は区別する。原本への上書き・保存競合解決、追加の文字コード、見開き、既存設定の移行、OSサンドボックス、実原稿を使う推論連携などは現在の比較で合格にしない。計測やUIが未確認の場合も合格にはしない。
- 自動検証・開発用アプリでの受け入れ・正式な世代交代は別の判定。最低OS、配布用署名・公証、App Storeの権限と移行を、オーナーが別途判断する。第一世代を削除したり、旧PRを合流したりしない。
