# v2.8 Plan — Local Assist Writing Companion

Status: Release preparation; physical validation pending
Scope: Apple Intelligenceで既存Local Assist体験を磨く開発線
Authority: Medium
Last reviewed: 2026-09-07

## Entry State

- Development-tree version: **`2.8.0`**. This is a development version, not
  an App Store/TestFlight package, upload, approval, publication, or GitHub tag.
- The local `2.7.0` / build `123` package is frozen separately at source
  checkpoint `d1db159a`. The owner plans to send it to App Review; Apple-side
  state remains user-owned and unconfirmed here.
- M-0a / H-1 System model reuse and the Rust-owned fail-closed backend wire are
  complete. No MLX runtime, model import, or model-selection UI exists.

## Goal

Make the current Apple Intelligence Local Assist feel like a quiet writing
companion while preserving the existing review boundary:

> 対象を確認して依頼し、未反映の案を育て、Diffを読んでから必要な場合だけ本文へ反映する。

This is not general chat, an autonomous rewrite agent, a model marketplace, or
approval to reopen the Apply path.

## Active Spine

### 1. U-1 — detached conversation-first companion

Implemented in PR #38/#39 and integrated with M-0a/H-1 for v2.8.
Owner correction 2026-09-06 supersedes the sidebar and draft-hero presentation.

Acceptance:

- Local Assist opens in its native separate window.
- A tall conversation log contains requests and app-known progress; the composer stays at the bottom.
- Target details, usage/requirements and presets start collapsed.
- The target stays pinned during follow-up revision; main Diff is the authoritative proposal review.
- Generation and cancellation use the existing Rust/helper path.
- Only explicit reviewed Apply changes the buffer; no auto-save.
- No renderer backend/model/path/provider controls are added.

### 2. U-3 — main Diff as the reading decision surface

Keep the current proposal's original-versus-candidate Diff authoritative.
Improve hierarchy and change-summary readability without changing
`applyReviewedLocalAssistProposal`, stale revalidation, Undo, or save behavior.

### 3. U-4 — model identity disclosure

Show the current System model identity as Apple Intelligence. This is disclosure
only. Download/manage/select stays in the later C-1/C-2 management lane.

### 4. G-1 — structured proofreading envelope

May follow after U-1 when it remains a self-contained slice. Diff is still the
review source of truth; `changeSummary` is supporting text and falls back to a
deterministic summary when sanitization changes the candidate.

## Verification

Each code slice follows `implementation → internal review → correction →
targeted tests → explicit stage → commit`.

Before a v2.8 package candidate:

```bash
npm run typecheck
npm test
npm run build:vite
cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
cargo test --manifest-path src-tauri/Cargo.toml
npm run smoke:app-store-surface
npm run build
git diff --check
```

Physical Local Assist generation, streaming cancel/retry, keyboard/focus, and
VoiceOver remain package-time evidence. Source checks do not substitute for
those interactions.

## Stop Conditions

- Do not change public TypeScript/Tauri backend selection or the Apply/save
  boundary as part of U-1.
- Stop and split the slice if it introduces provider configuration, arbitrary
  paths/URLs, network inference, tool calling, background indexing, auto-apply,
  auto-save, or multi-file agent behavior.
- Do not describe `2.8.0` as packaged, submitted, approved, or published until
  that separate evidence exists.
