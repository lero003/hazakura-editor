# Hazakura Editor 第二世代 開発状況ダッシュボード（PR #71）

PR #71（ブランチ `next-native-editor` / 実装領域 `next/`）の開発現在地・第一世代との比較・安全性・実機受け入れ・残課題を俯瞰するための独立した開発管制室ダッシュボードです。

## 構成ファイル

- `dashboard.html`: 単体で閲覧できる完成済みHTMLダッシュボード。CSS・Vanilla JS・共通ロジック・JSONデータを内蔵し、サーバー不要・オフライン・Safariの `file://` 直開きに対応します。
- `dashboard-data.json`: 機械取得統計（`mechanical`）と定性評価・根拠（`evaluation`）を分離した構造化データ（schema 1.1.0）。
- `dashboard-core.cjs`: スキーマ検証・URL安全性・CI判定・進捗/受入集計・SHA来歴・差分計算の共通ロジック。Node.jsの回帰テストと `dashboard.html` の双方から利用します。外部依存はありません。
- `dashboard.test.mjs`: Node.js標準テストランナーによる回帰テスト。
- `generate.mjs`: Node.js 標準モジュールのみで動作する再生成スクリプト。Git・GitHub CLI・`next/` から最新メトリクスを取得し、導出値を再計算して `dashboard-data.json` と `dashboard.html` の埋め込みJSON・共通ロジックを同期します。
- `screenshots/`: デスクトップ（ライト/ダーク）とモバイル幅の確認用スクリーンショット。
- `README.md`: 本ファイル（更新方法・判定基準・制約）。

## 更新・再生成方法

リポジトリルートから実行します（外部npmパッケージ不要）。

```bash
node next-dashboard/generate.mjs
```

再生成時は、`dashboard.html` 内の `DASHBOARD_CORE_START/END` と `DASHBOARD_DATA_START/END` の間を同期します。`dashboard-core.cjs` だけを編集してHTMLを再生成しないと、回帰テスト（埋め込みコアの一致確認）が失敗します。

### オプション

- `--skip-github`: オフライン環境等で `gh` CLI による PR #71 / Actions API 取得をスキップします。
- 通信失敗時・未認証時は取得失敗項目を推測値で補完せず、`fetchStatus: "failed"` とし、CIは「取得不能」として表示します。

## データの二層と鮮度

1. `mechanical` 層（コミット一覧、差分統計、CI状態、`next/` ファイル数・行数・`@Test` 数、GitHub PR情報）は実行時点の最新値に更新されます。
2. `evaluation` 層（フェーズ判定、第一世代との機能比較、安全性評価、UI/UX評価、残課題）は、`evaluatedCommitSha` と `evaluatedAt` を保持します。

最新HEADと評価対象SHAが異なる場合、`next/` の製品コード変更を含むか、ダッシュボード・文書・CIのみかを `evaluationImpact` として区別します。next/ の製品コード変更を伴わない差分（ダッシュボード・文書・CIのみ）は「評価対象HEADが古い（製品コード変更なし）」と表示し、製品コード変更がある場合は更新を促します。旧HEADの成功を最新HEADの成功として扱いません。

## CI状態の判定

`statusCheckRollup` はPRの現在の `headRefOid` に紐づくcheckとして扱い、`recentRuns` は `headSha` を照合します。以下の状態を区別します。

| 状態 | 意味 |
|---|---|
| `success` | 最新HEADに紐づく全ワークフローが成功 |
| `failure` | 最新HEADに紐づくワークフローが失敗 |
| `running` | 最新HEADに紐づくワークフローが実行中 |
| `partial` | 一部のワークフローだけ最新HEADの結果がある（他は未取得・旧HEADのみ） |
| `stale` | 最新HEADの結果がなく、旧HEADの成功記録のみがある |
| `unavailable` | GitHub取得失敗・`--skip-github`・対象HEAD不明などで取得不能 |

`dashboard.html` は上記を保存データから毎回導出し、旧HEADの成功記録は別表（「根拠・対象SHA」）に分離します。テスト数のような実行結果はソース集計（`@Test` 数）とCI最終成功時の記録（対象SHA付き）を区別して表示します。

## 対象SHAの来歴

Git HEAD・GitHub PR `headRefOid`・ソース集計HEAD・定性評価対象SHA・データ対象HEADを個別に表示し、一致・不一致・比較不能を区別します。評価根拠リンクは、原則として定性評価の対象SHA（`evaluatedCommitSha`）に固定します。評価対象SHAが不明な場合はリンクを生成せず、チップを無効表示にします。

## カタログ数・受入項目数・進捗率

現行データでは、機能カタログ **36項目**、うち「保留・対象外」**1件**（Agent Workbench）を除く **35項目** を進捗率の分母とします。分母には「保留（将来検討）」**6件**を含み、実装重み0として計上します（対象外とは区別）。この内訳は保存データから毎回再計算し、計算式の説明にも反映します。

実機受け入れは `acceptanceRows` の明細 **24項目** から、合格・不合格・未測定・対象外を再集計します。静的な `acceptanceSummary` と明細がずれた場合は、明細側の値を採用して警告を表示します。

進捗率は2つの指標に分離しています。

1. **機能・試作到達度**: 実装状態の重み平均（`未着手=0.0`, `調査・設計中=0.15`, `部分実装=0.40`, `試作実装=0.65`, `実装済み=1.0`）を対象内項目数で割った値。
2. **製品品質到達度**: 実装30% + 自動検証30% + 実機受け入れ40% の3軸加重平均を対象内項目数で割った値。自動検証は `未実施=0`, `部分検証=0.5`, `自動検証済み=1.0`、実機受け入れは `未着手=0`, `補助計測のみ=0.25`, `実機受け入れ済み=1.0`。

重大な安全性・実機ゲートが残る場合は、数値に関わらず警告を表示します。

## 画面構成（タブ）

トップの「概要」タブは、開発の現在地を10秒程度で把握できるよう次の4要素だけを表示します。

1. **実装到達度**: 対象内35項目の重み付き平均（未着手・部分・試作・実装済みの内訳バー付き）。
2. **製品品質**: 実装30%・自動検証30%・実機40%の3軸。
3. **開発ロードマップ**: 公式 Phase 0–5 の状態と、フェーズごとの済/残件数。
4. **次に取り組む3件**: 優先度・担当（エージェント推定）と、残課題・担当の集計。

詳細は次のタブへ分離しています。

| タブ | 内容 |
|---|---|
| 課題 | 13件の残課題、検索・優先度・担当フィルタ、完了条件、依存関係 |
| 機能比較 | 36項目、分類・実装状態フィルタ、実装/自動検証/実機の状態 |
| 品質・安全 | 安全マトリクス、バンドル別の検証境界 |
| 実機検証 | 合格・未測定・不合格・対象外、明細一覧、性能比較 |
| CI | 最新HEADのCI、旧HEADの成功記録、最終成功時の記録 |
| 履歴 | 意味のある開発クラスタ、全コミット検索 |
| 根拠 | 対象SHAの来歴、進捗率の定義、矛盾・乖離、モジュール規模、検証警告、前回差分 |

- 初期表示は「概要」のみで、他のタブは `hidden` です。長い説明は `details` で折りたたみます。
- タブはクリックのほか、フォーカス中の ←→ / Home / End で移動できます。`#issues` などのURLハッシュで直接開けます。
- 前回表示データがある場合は、概要に「前回表示から: 実機結果 1 件変化」のような差分1行を表示します。
- 優先度・推奨順序・依存関係・並行可否はエージェントの推定であり、公式ロードマップの決定事項ではありません。課題タブと概要にその旨を明示しています。
- データ生成日時と定性評価日時は別々に表示します。

## 前回評価との差分・JSON読み込み

- 正常に表示したデータをブラウザ内（`localStorage`）に保持し、次回表示時に進捗・CI/SHA・機能状態・受入結果・課題の差分を表示します。
- JSON読み込み時は、必須構造・日時・schemaVersion・GitHub URL・証拠パスの安全性を検証します。検証失敗時は既存の表示を保持し、エラーだけを通知します。
- 外部リンクは https のみ、資格情報付きURL・http・javascript/data URLはリンクしません。リポジトリ内の証拠パスは `..`・絶対パス・バックスラッシュ・パーセントエンコードされた迂回を拒否します。
- 読み込んだJSONの検証警告は「根拠・対象SHA」に表示します。

## 回帰テスト

外部依存なしで実行できます。

```bash
node --test next-dashboard/dashboard.test.mjs
```

CI失敗、実機合格、取得失敗、HEAD変更、機能追加、受入結果変更、課題追加、危険URL、スキーマ不正、埋め込みコア/JSONの同期、ハードコード数値の残存を模擬データで検証します。`Quality` ワークフローの `frontend` ジョブでも同じテストを実行します。

## 制約・セキュリティ衛生

- 外部ライブラリ・CDN・外部フォントへの依存は一切ありません。
- コミットメッセージやPR本文などの外部文字列はHTML生成時にすべてエスケープし、認証情報・ローカル絶対パス・証明書情報は出力しません。
- このディレクトリは独立した可視化成果物であり、第一世代・第二世代の製品コードおよび公式ロードマップ・作業キューは変更しません。
- 画面確認は通常のChrome/Safariで行います。専用ブラウザーやPlaywrightの導入は前提にしません。
