# Hazakura Editor 第二世代 開発状況ダッシュボード（PR #71）

PR #71（ブランチ `next-native-editor` / 実装領域 `next/`）の開発現在地・第一世代との比較・安全性・実機受け入れ・残課題を俯瞰するための独立した開発管制室ダッシュボードです。

## 構成ファイル

- `dashboard.html`: 単体で閲覧できる完成済みHTMLダッシュボード（CSS・Vanilla JS・JSONデータを内蔵し、サーバー不要・オフライン・Safariの `file://` 直開きに対応）。
- `dashboard-data.json`: 機械取得統計（`mechanical`）と定性評価・根拠（`evaluation`）を分離した構造化データ。
- `generate.mjs`: Node.js 標準モジュールのみで動作する再生成スクリプト。Git・GitHub CLI・`next/` から最新メトリクスを取得し、`dashboard-data.json` と `dashboard.html` の埋め込みJSONを更新する。
- `screenshots/`: デスクトップ表示（1440×900）の確認用スクリーンショット。
- `README.md`: 本ファイル（更新方法・判定基準・制約）。

## 更新・再生成方法

リポジトリルートから以下を実行します（外部npmパッケージ不要）。

```bash
node next-dashboard/generate.mjs
```

### オプション

- `--skip-github`: オフライン環境等で `gh` CLI による PR #71 / Actions API 取得をスキップします。
- 通信失敗時・未認証時は取得失敗項目を推測値で補完せず、`fetchStatus: "failed"` とし画面上部に警告バナーおよび「不明」を表示します。

### 再生成時の重要な挙動（古い評価を最新扱いしない仕組み）

1. `mechanical` 層（コミット一覧、差分統計、CI状態、`next/` ファイル数・行数・`@Test` 数）は実行時点の最新値に更新されます。
2. `evaluation` 層（フェーズ判定、第一世代との機能比較、安全性評価、UI/UX評価、残課題）は、`evaluatedCommitSha` と `evaluatedAt` を保持します。
3. PR #71 の最新 HEAD が `evaluatedCommitSha` と異なる場合、`evaluation.isStaleRelativeToHead` が自動的に `true` となり、ダッシュボード最上部に「定性評価の更新が必要」である旨の警告バナーを表示します。コード・設計文書の再精査後に `dashboard-data.json` の `evaluation` と `evaluatedCommitSha` を更新してください。

## 状態の判定ルール（10区分）

色のみに依存しないよう、各状態に記号・文字ラベル・枠線スタイルを組み合わせています。

| 状態 | 記号 | 定義 |
|---|---|---|
| `未着手` | ○ | 第二世代で未着手 |
| `調査・設計中` | ◌ | 契約・境界・方式を比較検討中 |
| `部分実装` | ◐ | 一部機能やコアのみ実装済み、主要経路が未接続 |
| `試作実装` | ◈ | 限定範囲・別バンドル・合成原稿向けの動作試作 |
| `実装済み` | ● | 予定スコープの実装が完了（検証・実機確認は別判定） |
| `自動検証済み` | ✓ | Swift Testing / CIで境界・回帰テストが通過 |
| `実機受け入れ済み` | ◆ | macOS実機GUI・IME・VoiceOver・比較手順で合格 |
| `製品化済み` | ★ | 配布署名・公証・移行を含め世代交代可能な状態 |
| `保留・対象外` | － | 方針により後続フェーズへ保留、またはG2では廃止・対象外 |
| `不明・未確認` | ？ | 証拠不足・未測定・外部環境未確認 |

実装・自動検証・実機受け入れは機能比較表において**それぞれ独立した3列**として管理しています。

## 進捗率の計算方法

進捗率は意図的に2つの異なる指標へ分離しています。対象カタログ全36項目のうち、`保留・対象外`（1件：`Agent Workbench`）を除外した **35項目** を分母とします。

1. **機能・試作到達度（一旦機能を作り切るまで）**
   - 実装軸の重み平均: `未着手=0.0`, `調査・設計中=0.15`, `部分実装=0.40`, `試作実装=0.65`, `実装済み=1.0`
   - 計算式: $\sum \text{実装重み} / 35 \times 100$
2. **製品品質到達度（製品品質に達するまで）**
   - 3軸の加重平均: `実装(30%) + 自動検証(30%) + 実機受け入れ(40%)`
   - 自動検証重み: `未実施/不明=0.0`, `部分検証=0.5`, `自動検証済み=1.0`
   - 実機受け入れ重み: `未着手/不明=0.0`, `補助計測のみ=0.25`, `実機受け入れ済み/製品化済み=1.0`
   - 計算式: $\sum (0.30 w_{\text{impl}} + 0.30 w_{\text{ver}} + 0.40 w_{\text{acc}}) / 35 \times 100$

重大な安全性・実機ゲート（実機受け入れ24項目未測定、原本上書き保存・競合解決未実装など）が残る場合は、数値に関わらずサマリー上部に警告を表示します。

## 制約・セキュリティ衛生

- 外部ライブラリ・CDN・外部フォントへの依存は一切ありません。
- コミットメッセージやPR本文などの外部文字列はHTML生成時にすべてエスケープし、認証情報・ローカル絶対パス・証明書情報は出力しません。
- このディレクトリは独立した可視化成果物であり、第一世代・第二世代の製品コードおよび公式ロードマップ・作業キューは変更しません。
