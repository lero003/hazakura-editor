# Hazakura Editor Next — ネイティブ技術検証

このディレクトリは、第一世代と独立した macOS アプリの開発用プロジェクトです。内蔵サンプル・空の原稿・選んだテキストの編集用コピーを別タブで扱い、原本には書き込まず新しいファイルにコピーを保存できます。配布版ではありません。方針・フェーズは[ロードマップ](../docs/roadmap.md#第二世代設計)を参照してください。

## ビルド・テスト・起動

開発ターゲットは暫定で macOS 26 以降。Swift 6.2 以上と対応する macOS SDK を使います。対応OS・Intel対応・配布方式の最終決定ではありません。npm、Cargo、外部 Swift パッケージは不要です。

リポジトリのルートから:

```bash
swift test --package-path next
bash next/scripts/run-dev.sh --build-only
bash next/scripts/run-dev.sh
bash next/scripts/run-dev.sh --long-sample
bash next/scripts/run-dev.sh --build-assist-review-demo
bash next/scripts/run-dev.sh --assist-review-demo
```

`--build-only` は `.build/` 配下に開発用 `.app` を作成し、ローカルのアドホック署名と整合性を確認します。配布署名や公証は行いません。通常起動と `--long-sample` はその `.app` を開き、後者は内蔵サンプルを繰り返して生成した長文を表示します。復旧領域を共有するアプリは同時に起動せず、サンプルを切り替えるには先に終了してください。Bundle ID は `dev.hazakura.editor.next.dev`（第一世代とは別）。第一世代の設定・保存場所は読み書きしません。原本への明示保存はまだ実装していません。復旧用の原文は第二世代開発版だけの Application Support 領域に、暗号化せずローカル保存します。内蔵テキストや合成ファイルで検証してください。

`--assist-review-demo` は通常版と別のデモ用 `.app`（Bundle ID `dev.hazakura.editor.next.assist-demo.dev`）を作って開きます。`--build-assist-review-demo` は同じデモを生成・署名検証しますが開きません。デモは Finder から開いても通常版に切り替わりません。通常版の実行ファイルはデモ用引数での直接起動を拒否します。内蔵原稿の「表記:」から「末尾」の行までを選び、「候補を確認…」で固定の合成候補と比較します。「合成候補を反映」を明示した場合だけ、元の編集面に戻って置換します。Undoで戻せます。「直近の採用差分…」（⌘⇧D）で、確認できた直近1件の選択範囲の差分を見返せます。これは採用時点の記録であり、Undoやその後の入力を反映しません。再適用はできず、デモ終了時に消えます。編集結果が原稿の状態に反映されていないときは、同じ編集面の確定本文と変更前のモデルを照合できた場合だけメモリ内で同期します。結果が確認できないときは警告し、候補の再適用や自動Undoは行いません。デモにファイルを開く・保存する・原稿を復旧する機能や、モデルへの送信・推論機能はありません。これはOSサンドボックスの検証ではないため、合成テキストだけで試してください。実機では、起動直後は採用差分を開けないこと、採用後に差分を開けること、記録のシートをEscで閉じて編集に戻れることを確認します。Undoは選択範囲の置換だけを戻し、後続の編集や次の候補の取消で記録は変わらず、別の採用で置き換わります。終了して開き直すと記録は残りません。

## 長文レイアウトの補助計測

```bash
swift run --package-path next -c release HazakuraNextLayoutProbe --measure
```

内蔵の合成原稿で、非表示のTextKit 2編集面の作成と初期レイアウト、幅を900 ptから550 ptへ変更したときのレイアウト、末尾行のレイアウトとその位置へのスクロールにかかる時間を5回測ります。JSONには試行ごとの値と最小・中央値・最大（マイクロ秒）を出力します。外部の原稿やパスは指定できず、通常版の設定・復旧記録には接続しません。アプリの起動時間や画面描画、IME、メモリ、第一世代との差は、この計測から判断しません。[受け入れ手順](../docs/next-native-acceptance.md#性能比較と記録)を別途実施してください。

## オンデバイス推論の比較プローブ

通常版・採用デモとは別のCLIです。`--check` はシステムモデルの利用可否だけを確認します。`--generate` は Apple のオンデバイスモデルで内蔵の合成文を1回言い換えます。`--compare` は同じ合成文を、新しいセッションで1回ずつ順に処理します。1回目が成功した場合にだけ2回目に進みます。

```bash
swift run --package-path next HazakuraNextModelProbe --check
swift run --package-path next HazakuraNextModelProbe --generate
swift run --package-path next HazakuraNextModelProbe --compare
```

任意の文章やファイルは渡せません。ツール、失敗時の再試行、モデルの取得要求、クラウドへの切替はありません。JSONには固定のモデル種別・合成例のID、各回の開始時点での利用可否と結果の状態を出し、成功時だけ所要時間（ミリ秒）とUTF-8バイト数を加えます。計測にはセッションの準備・応答・結果の検査を含め、Swiftのビルド時間や実行ファイルの起動時間は含めません。本文やSDKエラーは出力しません。

`--compare` のJSONは `first` と、実施結果がある場合の `second` を返します。両方が成功した場合だけ終了コード0です。生成する各モードで、利用不可は3、生成失敗や応答の形式・上限の違反は1、試行の待機期限（`timedOut`）は124、Swiftタスクの取消は130です。`--check` は利用不可でも照会結果を返せば0です。

推論の待機期限は各回30秒です。期限を過ぎたらCLIが結果を返して終了し、モデルを呼ぶSwiftタスクの取消は別タスクで試みます。CLIがその処理より先に終了することもあり、遅れた応答は記録しません。利用可否の照会・ビルド・起動は期限に含みません。メインアクターが同期処理で塞がる場合の応答時間や、OS側の推論が止まることは保証しません。端末からの割り込みでJSONを返す仕組みはありません。

同じMac・OS・Apple Intelligence設定で `first` と `second` を比較します。キャッシュは制御しないため、コールド起動とウォーム起動の測定ではありません。`completed` は上限内の応答が返ったことを示すだけで、日本語の品質や打ち切りの有無は判定しません。

## 検証すること・まだ検証しないこと

同じMac・合成原稿で両世代を実機比較する場合は、[受け入れ手順](../docs/next-native-acceptance.md)を参照してください。

- **タブと終了:** `⌘T` で空のタブを作成し、タブ名をクリックして切り替えます（最大8件）。編集済みの原稿があれば、タブを閉じるときもウィンドウを閉じるとき（赤ボタン・`⌘W`）も、アプリを終了するとき（`⌘Q`）も、破棄を確認します。変換中は終了せず、確定または取消を待ちます。破棄に同意すると、該当タブの復旧記録も削除します。削除に失敗した場合は原稿を閉じません。
- **原文を検索:** 「編集」→「原文を検索…」（`⌘F`）で、選択中のタブの確定原文（UTF-8換算2 MiB以下）を検索します。CR・LFを含まない空でない文字列（512バイトまで）をそのまま照合し、先頭から最大64件の行番号を表示します。大文字・小文字や合成済みの文字と結合文字は区別し、絵文字や結合文字の途中だけに一致する候補、すでに表示した一致と重なる候補は除外します。正規表現・置換・他のタブの検索は行いません。結果を選ぶとシートを閉じ、同じ版の一致箇所を選択します。検索語はシートにだけ、結果は操作中のメモリにだけ保持し、検索専用のシステム共有ペーストボードには書き込みません。
- **原文の行へ移動:** 「表示」→「原文の行へ移動…」（`⌘L`）で、選択中のタブの指定行の先頭へ移動します。行番号は半角数字で1から数え、折り返しは数えません。CR・LF・CRLFを区切りとし、末尾改行の後の空行も指定できます。UTF-8換算で2 MiB以下の確定原文が対象です。範囲外・変換中・原稿の版が変わった場合は移動せず、原文・Undo履歴・復旧記録は変更しません。
- **退避と復元:** 編集の確定後に、読み取り専用タブを除く原稿を短い間隔で退避します。選択中の原稿では、現在の確定版の書込みが成功した場合だけ「この版は復旧用に退避済み」と表示します。原稿ファイルへの保存とは別で、再編集後は新しい版を確認するまで「この版の復旧用退避は未確認」になります。文字変換中や破棄処理中、退避対象でないタブでは、この表示は出ません。再起動後は「原稿を復元」ボタンで、書き込み済みの記録を確認して別の未保存タブに開けます。復元しても元の復旧記録は残ります。一覧の「記録を削除…」は、確認した記録とID・版・本文の全バイトが一致した場合にだけ削除します。記録が変わったり消えていたりした場合は、削除せず一覧を読み直します。1件の上限はUTF-8換算で2 MiBです。ディスク上のUTF-16が2 MiB以内でも、換算後に上限を超える原稿は退避できません。全体の上限は32件、合計16 MiBで、既存記録の自動削除はしません。直前の未確定入力や未書き込みの編集、電源断での復元は保証しません。
- **ファイルを読む:** `⌘O` またはフォルダボタンで2 MiB以下のテキストを1件選びます。UTF-8（BOMの有無を問わない）とBOM付きUTF-16（LE/BE）に対応します。BOMのない入力はUTF-8としてのみ読みます。不正な符号列、UTF-32 BOM、テキストでない制御文字、リンクを含むパスは受け付けません。読み取り専用タブに開き、文字コード・BOM・混在した改行・元バイトを保持し、元ファイルには書き込みません。外部更新はファイルを再選択するまで反映されません。
- **フォルダの原稿一覧（試作）:** 「ファイル」→「フォルダの原稿一覧…」でローカルのフォルダを1つ選ぶと、直下の通常ファイルのうち `.md`、`.markdown`、`.txt` の候補名を表示します。シンボリックリンクとサブフォルダをたどらず、ドットで始まる名前とOSの `UF_HIDDEN` フラグ付きのファイルは表示しません（Finderと同じ一覧ではありません）。直下のハードリンクは通常ファイルとして扱います。直下の全項目を数え、512件を超えた場合は部分的な一覧も表示しません。一覧を取得するだけでは本文を読み込みません。1件選んで「この原稿を選ぶ」を押し、元のウィンドウで「同じフォルダを選び直す…」を押します。フォルダと選んだ項目の識別・版を確認できた場合にだけ、その1件を読み取り専用の新規タブで開きます。別のフォルダを選んだ場合や一覧取得後の変更を検出した場合は、一覧を取り直してください。フォルダのパスや権限は次の操作に引き継がず、一覧からの変更・自動更新も行いません。実機ではフォルダ選択の確定・取消、Esc、操作後の編集フォーカスと権限を確認します。
- **編集用コピーと新規保存:** 読み取り専用の原文から「編集用コピーを開く」で別の未保存タブを作ります。「コピーを保存…」（`⌘⇧S`）で新しいファイル名を選びます。既存のファイルは置き換えず、原本や編集中のタブも変更しません。保存先は自分が所有し、他の利用者に書込みを許していないローカルフォルダに限ります。書込み中に強制終了すると、保存先フォルダに本人だけが読める一時ファイルが残る場合があります。編集用コピーは、開いた時点の文字コード・BOM（UTF-16ではLE/BEも）と、編集後の改行を保って保存します（保存先の符号化でBOM込み2 MiBまで）。新規原稿と復旧記録から開き直した原稿のコピーはUTF-8で保存し、BOMは付加しません。作成後は選択中のタブに「この版のコピーを作成済み」と表示します。再編集後は「以前の版のコピーを作成済み」に変わります。コピー作成時の記録であり、元のファイルの保存や出力先ファイルの現在の状態を示すものではありません。表示はタブを閉じると消え、破棄確認や復旧には影響しません。
- **原本の版を比較:** 編集用コピーで「原本の版を比較…」を選び、原本を再選択します。開いた時点・今回選択したディスク版・手元の編集版を読み取り専用で確認できます。ファイル識別とバイトの一致を分け、同じ名前でも置き換えや別ファイルを変更なしとは扱いません。本文表示は先頭16 KiBまで、一致判定は全体を対象にします。同じファイルと判定され、バイト列が変わっていた場合は「比較時のディスク版を別タブで開く」で、読み取った時点の本文全体を読み取り専用タブに開けます。タブ名には「比較時：」が付きます。手元の編集版を置き換えず、開く時にファイルを読み直しません。タブ上限・変換中・編集版の状態が比較時と異なる場合は開けません。原本への上書きや自動更新は行いません。
- **行の差分（Non-Git）:** 比較画面の「行の差分を見る」で3つの版から2つを選べます。追加・削除と両側の行番号を表示し、LF・CRLF・CR・末尾改行なしも区別します。文字コードやBOMの違いは概要に表示し、本文の行差分がなくてもバイトの不一致として扱います。長い行は先頭1 KiBだけ表示しますが、行の判定には行全体を使います。デコードした本文2版の合計（UTF-8換算）4 MiB・12,000行、または照合処理の上限を超える場合は行差分を表示せず、「版ごとに読む」と全体の一致判定は引き続き使えます。差分から編集や保存は行いません。
- **えるモード（試作）:** 「表示」→「えるモード」で、原稿の左右と上下に余白を取り、本文を中央寄りに表示します。Markdownの記号は隠さず、選択・編集・Undo/Redoは同じエディタで続けられます。文字変換中や書き出しなどの操作中は切り替えません。この切替はウィンドウを開いている間だけ有効で、原稿・保存・復旧記録には影響しません。
- **外観（試作）:** 「表示」→「外観」で「システム設定に従う」「ライト」「ダーク」を選べます。設定はこのウィンドウにだけ適用され、閉じると消えます。色はmacOS標準の外観を使い、第一世代のテーマを読み込んだり、原稿・保存・書き出し内容を変更したりしません。変換中やファイル操作中は切り替えられません。実機では編集面とプレビューの可読性、選択色、システム設定へ戻したときの追従を確認します。
- **集中表示（試作）:** 「表示」→「集中表示」（`⌘⇧J`）でタブ列とツールボタンを隠します。現在の原稿名、読み取り専用の表示、復旧などの通知は残ります。「集中表示を終了」または同じキーでタブ列に戻れます。タブの切替や「原稿を復元」は通常表示に戻って操作してください。えるモードとは別に切り替えられ、文字変換中やファイル操作中は切り替えません。設定はウィンドウを閉じると消えます。実機では切替前後の選択・Undo・入力フォーカスと、Tabで終了ボタンに移動してSpaceで解除した後に編集へ戻れることを確認します。
- **Markdownプレビュー:** 「表示」メニューまたはツールバーから、選択タブの確定原文を読み取り専用で表示します。入力中の変換候補は使いません。開いた時点の内容を表示し、原稿・保存・退避記録は変更しません。見出し、強調、引用、リスト、コードを表示します。「目次を表示」で見出しを一覧にし、選んだ見出しまでプレビュー内を移動できます。同名の見出しも別々に扱います。同じタブ・同じ版で開き直すと、最後にスクロールで表示した本文ブロック、または目次や本文検索で移動した位置から再開します。位置はメモリにだけ保持し、編集・タブを閉じる操作・アプリの再起動をまたぎません。「原文の○行目へ」がある見出しでは、プレビューを閉じて現在のタブの該当行に移動します。原文の位置が確認できない場合や、表示後に編集が確定して版が変わった場合は移動しません。リンクは開かず、画像や外部・ローカルの参照先を読み込みません。HTMLの描画・実行は行いません。Markdownの表は、システムの解析結果で8列・見出し行込み32行までを、プレビュー・複数原稿の読書画面・HTML/PDF/EPUBで表示します。表の上限を超えたり行・列を確認できなかったりした場合は、表全体を表示できない旨に置き換えます。空欄だけの表・末尾の空行など、解析結果に現れない部分は表示されません。列の揃え指定は反映しません。128 KiB・2,000ブロックまたは変換処理の上限を超える場合は、プレビューを表示せず原文に戻れます。
- **章ごとに読む:** Markdownプレビューで「章ごとに読む」を押すと、現在の位置を含む章だけが表示されます。引用やリストの外にあるレベル1・2の見出しを章の区切りとし、最初の見出しより前も読めます。区切りがなければ本文を1章として扱います。前後の章に進むか、目次から別の章・章内の見出しに移動できます。「全文を表示」で同じ位置から全文に戻れます。章表示の切替そのものは記録せず、読書位置だけを同じタブ・同じ版のプレビューで共有します。ページ送りは未対応です。
- **開いている原稿を続けて読む（試作）:** 「表示」→「開いている原稿を続けて読む…」で、開いているタブから2件以上を選びます。「選んだ原稿を読む」を押した時点の確定原文をタブ順に固定し、「前の原稿」「次の原稿」で切り替えます。空の原稿も飛ばさず、表示上限に達した原稿があれば一部だけ表示することはありません。最大8件、1件128 KiBかつ合計256 KiB（UTF-8）です。ファイルは再読込みせず、原稿・タブの選択・復旧記録は変えません。「本文を検索」では選んだ原稿の表示本文だけをタブ順に探し、前後の一致へ移動する際は必要に応じて原稿も切り替えます。原稿名、リンク先、未選択の原稿は対象外です。検索語と結果は検索欄を閉じると消えます。本の構成や読書位置の保存、見開きは未対応です。実機ではキーボードでの選択・原稿の切替・検索位置へのスクロール・Esc・編集フォーカスの復帰を確認します。
- **単一原稿プレビューの本文検索:** 「本文を検索」を開き、語句を入力して「検索」を押します。全文・章表示とも、開いたときのプレビューで表示するテキストから、段落や見出しなどのブロック単位で探します。最初の一致へ移動し、「前の一致へ」「次の一致へ」で別の章の結果にも進めます。先頭・末尾では折り返しません。現在の結果は枠で示します。大文字・小文字は区別せず、1ブロックに複数回出ても1件と数えます。表はセル内だけを照合し、複数のセルが一致しても表全体を1件とします。セルやブロックをまたぐ一致は探しません。語句はUTF-8で512バイトまでで、入力を変えると前の結果が消えます。リンクや画像の参照先、非表示のHTML、ほかのファイルは検索しません。検索欄を閉じると語句と結果は消え、原文の編集・置換は行いません。
- **HTMLを書き出す:** 「ファイル」→「HTMLを書き出す…」で、選択中のタブの確定原文を新しい `.html` に書き出します。プレビューと同じ入力・構造上限があり、HTMLは原稿の文字コードによらずBOMなしUTF-8で、2 MiB以下です。リンク先や画像は埋め込まず、原稿中のHTMLは実行しません。書き出し先はコピー保存と同じ条件で、既存のファイルは置き換えません。保存ダイアログを取り消した場合や、書込み開始前に原稿の版が変わった場合は書き込みません。書き出しても原稿や退避記録は変わりません。
- **PDFを書き出す（試作）:** 「ファイル」→「PDFを書き出す…」で、同じ確定原文から新しい `.pdf` を作ります。アプリが生成したHTMLだけを内部のWebKitでPDFに変換し、印刷画面や外部アプリは開きません。縦長の1ページで、プレビューと同じ入力上限、描画範囲（幅720・高さ12,000 ptまで）、出力サイズ（16 MiB）のいずれかを超える場合は書き出しません。用紙指定・改ページは未対応です。上書き禁止と原稿・退避記録を変更しない点はHTMLと同じです。
- **EPUBを書き出す（試作）:** 「ファイル」→「EPUBを書き出す…」で、確定原文を章と目次付きの新しい `.epub` に書き出します。区切りは「章ごとに読む」と共通で、目次のリンクは本の内部だけに向きます。プレビューと同じ入力上限に加え、最大128章・16 MiBです。画像・外部リンク・原稿中のHTMLは有効にしません。書名は固定で、原稿の言語を推定しません。表紙やメタデータの編集、外部検証ツールのアプリからの起動はありません。上書き禁止と原稿・退避記録を変更しない点はHTMLと同じです。
- **選んだ原稿を1冊のEPUBに（試作）:** 複数原稿の読書画面で「選んだ原稿をEPUBに…」を押し、元のウィンドウで「書き出し先を選ぶ…」を押します。確認済みの本文をタブ順に、1原稿を1章としてまとめます。目次は「原稿 1」などの番号で、元ファイル名は書誌情報に含めません。空の原稿も空である旨を表示します。書込み開始前に原稿の版が変わった場合、保存先を取り消した場合、既存名を選んだ場合は書き出しません。ファイルは再読込みせず、複数原稿プレビューの入力上限とEPUBの16 MiB上限を適用します。
- **提案差分の表示サンプル:** 「開発用」→「提案差分の表示サンプル…」で、内蔵の合成テキストだけを読み取り専用で比較します。空白・タブ・不可視文字を記号で表示し、LF・CRLF・CR・改行なしを区別します。Unicodeスカラーのコード表示をオンにすると、見た目が同じでも異なる文字列を確認できます。行番号は選択範囲内です。編集中の原稿の読取り・採用・AI推論は行いません。実機では文字の折り返し、VoiceOver、Escで閉じた後の編集フォーカスを確認します。
- **原本保存の事前検証（コアのみ）:** 開いた時点と選び直したファイルの識別情報・版情報・全バイトを照合し、同意後に同じ選択先を再読込します。変更や読込不能なら確認を打ち切ります。この検証は読み取り専用で、成功しても書込み権限や直後のファイル状態を保証しません。原本を書き換える画面・操作はありません。
- `HazakuraNextCore` は文書 ID ごとに確定原文と編集リビジョンを保持し、開いたファイルのスナップショットを別に扱います。後で使うためのファイルアクセス権や原本パスは復旧記録に保存しません。
- `HazakuraNextEditor` はタブごとに AppKit の TextKit 2 を保持し、選択範囲とUndo/Redo履歴を分けます。変換途中の候補は原文に反映せず、確定または取消までタブの追加・切替・破棄を止めます。
- 実機の受け入れでは、開く／保存するダイアログと権限（選択した新規ファイルへの書き込み）、HTML/PDF/EPUB書き出しの確定・ダイアログでの取消・既存名の拒否、ブラウザーや閲覧アプリでの見え方（日本語と原稿末尾、EPUBの章・目次移動）、変換の確定・取消、文字列や選択範囲の保持、Undo/Redo、強制終了後の復元、長文の折り返し、差分の版切替、目次の表示切替と同名・末尾の見出しへのスクロール、章表示と全文表示を切り替えたときの読み始め、前後の章・目次の操作、日本語の検索入力・章境界や末尾の一致への移動・検索を閉じた後の再開位置、同じ版を開き直したときの再開位置、原文に戻った直後の編集フォーカス・Undo、えるモード往復時の選択とカーソル、長い日本語行の折り返しと変換中のウィンドウ幅変更、キーボード操作・VoiceOver、起動と入力応答、メモリを確認します。自動試験とビルドの成功はこの受け入れを代替しません。原本への保存・競合解決、UTF-8／BOM付きUTF-16以外の符号化、サンドボックス、配布、エディタとの推論連携は未実装です。
