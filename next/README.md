# Hazakura Editor Next — ネイティブ技術検証

このディレクトリは、第一世代と独立した macOS アプリの開発用プロジェクトです。内蔵サンプル・空の原稿・選んだUTF-8テキストの編集用コピーを別タブで扱い、原本には書き込まず新しいファイルにコピーを保存できます。配布版ではありません。方針・フェーズは[ロードマップ](../docs/roadmap.md#第二世代設計)を参照してください。

## ビルド・テスト・起動

開発ターゲットは暫定で macOS 26 以降。Swift 6.2 以上と対応する macOS SDK を使います。対応OS・Intel対応・配布方式の最終決定ではありません。npm、Cargo、外部 Swift パッケージは不要です。

リポジトリのルートから:

```bash
swift test --package-path next
bash next/scripts/run-dev.sh --build-only
bash next/scripts/run-dev.sh
bash next/scripts/run-dev.sh --long-sample
bash next/scripts/run-dev.sh --build-assist-review-demo
bash next/scripts/run-dev.sh --assist-review-demo
```

`--build-only` は `.build/` 配下に開発用 `.app` を作成し、ローカルのアドホック署名と整合性を確認します。配布署名や公証は行いません。通常起動と `--long-sample` はその `.app` を開き、後者は内蔵サンプルを繰り返して生成した長文を表示します。復旧領域を共有するアプリは同時に起動せず、サンプルを切り替えるには先に終了してください。Bundle ID は `dev.hazakura.editor.next.dev`（第一世代とは別）。第一世代の設定・保存場所は読み書きしません。原本への明示保存はまだ実装していません。復旧用の原文は第二世代開発版だけの Application Support 領域に、暗号化せずローカル保存します。内蔵テキストや合成ファイルで検証してください。

`--assist-review-demo` は通常版と別のデモ用 `.app`（Bundle ID `dev.hazakura.editor.next.assist-demo.dev`）を作って開きます。`--build-assist-review-demo` は同じデモを生成・署名検証しますが開きません。デモは Finder から開いても通常版に切り替わりません。通常版の実行ファイルはデモ用引数での直接起動を拒否します。内蔵原稿の「表記:」から「末尾」の行までを選び、「候補を確認…」で固定の合成候補と比較します。「合成候補を反映」を明示した場合だけ、元の編集面に戻って置換します。Undoで戻せます。デモにファイルを開く・保存する・原稿を復旧する機能や、モデルへの送信・推論機能はありません。これはOSサンドボックスの検証ではないため、合成テキストだけで試してください。実機ではシートをEscで取り消しても本文が変わらないこと、採用後に元の編集面で入力でき、Undoが選択範囲の置換だけを戻すことを確認します。

## オンデバイス推論の比較プローブ

通常版・採用デモとは別のCLIです。`--check` はシステムモデルの利用可否だけを確認し、`--generate` を明示した場合だけ Apple のオンデバイスモデルで内蔵の合成文を1回言い換えます。

```bash
swift run --package-path next HazakuraNextModelProbe --check
swift run --package-path next HazakuraNextModelProbe --generate
```

任意の文章やファイルは渡せません。ツール、再試行、モデルの取得要求、クラウドへの切替はありません。JSONには開始時点の利用可否と結果の状態を出し、成功時だけ応答時間（ミリ秒）・UTF-8バイト数を加えます。本文やSDKエラーは出力しません。`--check` は利用不可でも照会に成功すれば終了コード0、`--generate` は利用不可なら3です。`completed` は上限内の応答が返ったことを示し、日本語の品質や打ち切りの有無を判定しません。実行時間やモデル側の即時停止は保証しません。

## 検証すること・まだ検証しないこと

- **タブと終了:** `⌘T` で空のタブを作成し、タブ名をクリックして切り替えます（最大8件）。編集済みの原稿があれば、タブを閉じるときもウィンドウを閉じるとき（赤ボタン・`⌘W`）も、アプリを終了するとき（`⌘Q`）も、破棄を確認します。変換中は終了せず、確定または取消を待ちます。破棄に同意すると、該当タブの復旧記録も削除します。削除に失敗した場合は原稿を閉じません。
- **退避と復元:** 編集の確定後に、読み取り専用タブを除く原稿を短い間隔で退避します。再起動後は「原稿を復元」ボタンで、書き込み済みの記録を確認して別の未保存タブに開けます。復元しても元の復旧記録は残り、一覧から確認のうえ削除できます。上限は1件2 MiB、32件、合計16 MiBで、既存記録の自動削除はしません。直前の未確定入力や未書き込みの編集、電源断での復元は保証しません。
- **ファイルを読む:** `⌘O` またはフォルダボタンで2 MiB以下のUTF-8テキストを1件選びます。読み取り専用タブに開き、元ファイルに書き込みません。BOMの有無と改行コード（混在を含む）、元のバイト列を保持します。リンクを含む渡されたパス、不正UTF-8、テキストでない制御文字は受け付けません。ファイルを再選択するまで外部更新は表示に反映されません。
- **編集用コピーと新規保存:** 読み取り専用の原文から「編集用コピーを開く」で別の未保存タブを作ります。「コピーを保存…」（`⌘⇧S`）で新しいファイル名を選びます。既存のファイルは置き換えず、原本や編集中のタブも変更しません。保存先は自分が所有し、他の利用者に書込みを許していないローカルフォルダに限ります。書込み中に強制終了すると、保存先フォルダに本人だけが読める一時ファイルが残る場合があります。UTF-8で、コピーに引き継いだBOMの有無と、編集後の改行を保って書き出します（BOM込みで2 MiBまで）。復旧記録から開いた原稿は本文のみを復元するため、BOMは引き継ぎません。
- **原本の版を比較:** 編集用コピーで「原本の版を比較…」を選び、原本を再選択します。開いた時点・今回選択したディスク版・手元の編集版を読み取り専用で確認できます。ファイル識別とバイトの一致を分け、同じ名前でも置き換えや別ファイルを変更なしとは扱いません。本文表示は先頭16 KiBまで、一致判定は全体を対象にします。表示は比較時点の記録で、原本の上書きや自動更新は行いません。
- **行の差分（Non-Git）:** 比較画面の「行の差分を見る」で3つの版から2つを選べます。追加・削除と両側の行番号を表示し、LF・CRLF・CR・末尾改行なしも区別します。ファイル先頭の BOM の違いは概要で確認します。長い行は先頭1 KiBだけ表示しますが、行の判定には行全体を使います。2版合計4 MiB・12,000行、または照合処理の上限を超える場合は行差分を表示せず、「版ごとに読む」と全体の一致判定は引き続き使えます。差分から編集や保存は行いません。
- **えるモード（試作）:** 「表示」→「えるモード」で、原稿の左右と上下に余白を取り、本文を中央寄りに表示します。Markdownの記号は隠さず、選択・編集・Undo/Redoは同じエディタで続けられます。文字変換中や書き出しなどの操作中は切り替えません。この切替はウィンドウを開いている間だけ有効で、原稿・保存・復旧記録には影響しません。
- **Markdownプレビュー:** 「表示」メニューまたはツールバーから、選択タブの確定原文を読み取り専用で表示します。入力中の変換候補は使いません。開いた時点の内容を表示し、原稿・保存・退避記録は変更しません。見出し、強調、引用、リスト、コードを表示します。「目次を表示」で見出しを一覧にし、選んだ見出しまでプレビュー内を移動できます。同名の見出しも別々に扱います。同じタブ・同じ版で開き直すと、最後にスクロールで表示した本文ブロック、または目次や本文検索で移動した位置から再開します。位置はメモリにだけ保持し、編集・タブを閉じる操作・アプリの再起動をまたぎません。「原文の○行目へ」がある見出しでは、プレビューを閉じて現在のタブの該当行に移動します。原文の位置が確認できない場合や、表示後に編集が確定して版が変わった場合は移動しません。リンクは開かず、画像や外部・ローカルの参照先を読み込みません。HTMLの描画・実行は行わず、表の整形は未対応です。128 KiB・2,000ブロックまたは変換処理の上限を超える場合は、プレビューを表示せず原文に戻れます。
- **章ごとに読む:** Markdownプレビューで「章ごとに読む」を押すと、現在の位置を含む章だけが表示されます。引用やリストの外にあるレベル1・2の見出しを章の区切りとし、最初の見出しより前も読めます。区切りがなければ本文を1章として扱います。前後の章に進むか、目次から別の章・章内の見出しに移動できます。「全文を表示」で同じ位置から全文に戻れます。章表示の切替そのものは記録せず、読書位置だけを同じタブ・同じ版のプレビューで共有します。複数ファイルの本やページ送りは未対応です。
- **プレビューの本文検索:** 「本文を検索」を開き、語句を入力して「検索」を押します。全文・章表示とも、開いたときのプレビューで表示するテキストから、段落や見出しなどのブロック単位で探します。最初の一致へ移動し、「前の一致へ」「次の一致へ」で別の章の結果にも進めます。先頭・末尾では折り返しません。現在の結果は枠で示します。大文字・小文字は区別せず、1ブロックに複数回出ても1件と数えます。ブロックをまたぐ一致は探しません。語句はUTF-8で512バイトまでで、入力を変えると前の結果が消えます。リンクや画像の参照先、非表示のHTML、ほかのファイルは検索しません。検索欄を閉じると語句と結果は消え、原文の編集・置換は行いません。
- **HTMLを書き出す:** 「ファイル」→「HTMLを書き出す…」で、選択中のタブの確定原文を新しい `.html` に書き出します。プレビューと同じ入力・構造上限があり、HTMLはUTF-8で2 MiB以下です。リンク先や画像は埋め込まず、原稿中のHTMLは実行しません。書き出し先はコピー保存と同じ条件で、既存のファイルは置き換えません。保存ダイアログを取り消した場合や、書込み開始前に原稿の版が変わった場合は書き込みません。書き出しても原稿や退避記録は変わりません。
- **PDFを書き出す（試作）:** 「ファイル」→「PDFを書き出す…」で、同じ確定原文から新しい `.pdf` を作ります。アプリが生成したHTMLだけを内部のWebKitでPDFに変換し、印刷画面や外部アプリは開きません。縦長の1ページで、プレビューと同じ入力上限、描画範囲（幅720・高さ12,000 ptまで）、出力サイズ（16 MiB）のいずれかを超える場合は書き出しません。用紙指定・改ページは未対応です。上書き禁止と原稿・退避記録を変更しない点はHTMLと同じです。
- **EPUBを書き出す（試作）:** 「ファイル」→「EPUBを書き出す…」で、確定原文を章と目次付きの新しい `.epub` に書き出します。区切りは「章ごとに読む」と共通で、目次のリンクは本の内部だけに向きます。プレビューと同じ入力上限に加え、最大128章・16 MiBです。画像・外部リンク・原稿中のHTMLは有効にしません。書名は固定で、原稿の言語を推定しません。表紙やメタデータの編集、外部検証ツールのアプリからの起動はありません。上書き禁止と原稿・退避記録を変更しない点はHTMLと同じです。
- **提案差分の表示サンプル:** 「開発用」→「提案差分の表示サンプル…」で、内蔵の合成テキストだけを読み取り専用で比較します。空白・タブ・不可視文字を記号で表示し、LF・CRLF・CR・改行なしを区別します。Unicodeスカラーのコード表示をオンにすると、見た目が同じでも異なる文字列を確認できます。行番号は選択範囲内です。編集中の原稿の読取り・採用・AI推論は行いません。実機では文字の折り返し、VoiceOver、Escで閉じた後の編集フォーカスを確認します。
- **原本保存の事前検証（コアのみ）:** 開いた時点と選び直したファイルの識別情報・版情報・全バイトを照合し、同意後に同じ選択先を再読込します。変更や読込不能なら確認を打ち切ります。この検証は読み取り専用で、成功しても書込み権限や直後のファイル状態を保証しません。原本を書き換える画面・操作はありません。
- `HazakuraNextCore` は文書 ID ごとに確定原文と編集リビジョンを保持し、開いたファイルのスナップショットを別に扱います。後で使うためのファイルアクセス権や原本パスは復旧記録に保存しません。
- `HazakuraNextEditor` はタブごとに AppKit の TextKit 2 を保持し、選択範囲とUndo/Redo履歴を分けます。変換途中の候補は原文に反映せず、確定または取消までタブの追加・切替・破棄を止めます。
- 実機の受け入れでは、開く／保存するダイアログと権限（選択した新規ファイルへの書き込み）、HTML/PDF/EPUB書き出しの確定・ダイアログでの取消・既存名の拒否、ブラウザーや閲覧アプリでの見え方（日本語と原稿末尾、EPUBの章・目次移動）、変換の確定・取消、文字列や選択範囲の保持、Undo/Redo、強制終了後の復元、長文の折り返し、差分の版切替、目次の表示切替と同名・末尾の見出しへのスクロール、章表示と全文表示を切り替えたときの読み始め、前後の章・目次の操作、日本語の検索入力・章境界や末尾の一致への移動・検索を閉じた後の再開位置、同じ版を開き直したときの再開位置、原文に戻った直後の編集フォーカス・Undo、えるモード往復時の選択とカーソル、長い日本語行の折り返しと変換中のウィンドウ幅変更、キーボード操作・VoiceOver、起動と入力応答、メモリを確認します。自動試験とビルドの成功はこの受け入れを代替しません。原本の編集・保存・競合解決、UTF-8以外の符号化、サンドボックス、配布、モデル推論は未実装です。
